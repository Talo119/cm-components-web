# 0004: Link

- **Status:** Implemented
- **Date:** 2026-11-07
- **Kind:** Simple
- **Depends on:** [0000](./0000-architecture.md), [0003](./0003-typography.md)

## Purpose

Gives projects a text link that uses the library's type scale and default look, works with any router, and meets WCAG 2.2 AA contrast on both color schemes. MUI's `Link` already renders an `<a>` on top of `Typography`, with underline control and `component` support, so this library adds a stable import, a link color that passes contrast in light mode, and a documented way to plug in a router. It adds no new behavior.

**Use it for:** links inside text, standalone text links such as "Forgot password?", and links that open a router page.

**Don't use it for:**

- Actions that don't navigate, such as "Show more". Use Button with `variant="text"`. `<Link component="button">` works, but see [Behavior and edge cases](#behavior-and-edge-cases).
- Links that should look like buttons. Use Button with `href` or `component`, as in [0001](./0001-button.md).
- Navigation menus, tabs and sidebars. Those are Navbar, Tabs and Sidebar on the [roadmap](./roadmap.md), which reuse the router setup described here.

## Usage

```tsx
import { Link, Typography } from '@cmotino/cm-web-components'
import { Link as RouterLink } from 'react-router'

<Typography>
  Read the <Link href="/terms">terms of service</Link> before you continue.
</Typography>

<Link href="https://mui.com" target="_blank" rel="noopener">MUI docs</Link>

<Link component={RouterLink} to="/settings">Settings</Link>

<Link href="/help" underline="hover" variant="body2">Need help?</Link>
```

**One router for the whole project.** A project that uses a router everywhere sets it once in its theme, and then writes `href` as usual:

```tsx
import { createCmTheme } from '@cmotino/cm-web-components'
import { Link as RouterLink } from 'react-router'
import type { ComponentProps, Ref } from 'react'

// Maps `href` to the router's `to`.
function LinkBehavior({ href, ref, ...props }: ComponentProps<'a'> & { ref?: Ref<HTMLAnchorElement> }) {
  return <RouterLink ref={ref} to={href ?? ''} {...props} />
}

const theme = createCmTheme({
  components: {
    MuiLink: { defaultProps: { component: LinkBehavior } },
    MuiButtonBase: { defaultProps: { LinkComponent: LinkBehavior } },
  },
})
```

`MuiLink` covers Link. `MuiButtonBase` covers Button with `href`, and any later component built on `ButtonBase`, such as Tabs and menu items. This answers the [roadmap question](./roadmap.md#questions-for-later-specs) for Link: the library doesn't depend on a router, and a project connects its router through `component` or the theme.

## API

`Link` is MUI's `Link`, re-exported from `src/components/Link/index.ts`. Every MUI prop works as documented by MUI 9. No props are added or removed.

```ts
export { default as Link } from '@mui/material/Link'
export type { LinkProps } from '@mui/material/Link'
```

The props a consumer uses most are `href`, `target`, `rel`, `component`, `underline`, `color` and `variant`. Their MUI defaults are kept: `underline="always"`, `color="primary"` and `variant="inherit"`, so a link takes the font of the text around it. The library changes only how `color="primary"` looks, through the theme (see [Styling hooks](#styling-hooks)).

**Why a re-export and not a wrapper:** the same reasons as in [0001](./0001-button.md#api). `Link` is an `OverridableComponent`, so a wrapper typed as `(props: LinkProps)` would lose the typing of `component={RouterLink} to="/x"`. If a later version needs its own props, a wrapper with the same type can replace the re-export without breaking consumers.

### Exceptions to the architecture spec

| Rule | Exception | Reason |
| --- | --- | --- |
| Section 2: every component accepts `slotProps` | Link has no `slotProps` | MUI's `Link` has a single root element and no slots in 9.5 |
| Section 6: `Link.tsx` and `Link.types.ts` | Neither file exists. The folder holds `index.ts`, `Link.test.tsx` and `Link.stories.tsx` | There is no component code or type of our own to put in them |

No `'use client'` directive is needed, because this module has no hooks and MUI's `Link` module carries its own.

## Data shapes

None. Text is passed as `children`.

## Variants and states

| Variant or state | Behavior or appearance |
| --- | --- |
| Default | `<a>` in the surrounding font, underlined, in `primary.dark` in light mode and `primary.main` in dark mode |
| `underline="hover"` | Underlined only on hover. Use it only where the link is clearly a link without the underline, such as a list of links. See Accessibility |
| `underline="none"` | Never underlined. Same caution as `hover` |
| `color` | `primary` is changed by the library as above. Other values, such as `secondary`, `error` or `inherit`, keep MUI's look. Their contrast is listed in [0003](./0003-typography.md#accessibility) |
| `variant` | Any Typography variant, such as `body2`. The default, `inherit`, takes the parent's font |
| Hover | The underline changes from a translucent primary color to the full text color, as in MUI |
| Keyboard focus | The theme's focus ring from [0001](./0001-button.md#styling-hooks): a solid 2px outline in `primary.main` |
| Disabled | Doesn't apply. HTML links can't be disabled. Remove `href`, or render plain text, when a link isn't available |
| Loading, empty, error | Don't apply |

## Styling hooks

- **Theme key:** `components.MuiLink`. New colors use MUI's `LinkPropsColorOverrides`, and Typography's variant overrides apply to `variant`. A project changes the router through `defaultProps.component`, as under Usage.
- **Slots:** None. The root element is reached with `classes` or `styleOverrides` keys: `root`, `underlineNone`, `underlineHover`, `underlineAlways`, `button` and `focusVisible`.
- **Default look:** MUI's link, with the font from the type scale in [0003](./0003-typography.md) and the color changed for contrast. `src/theme/defaultTheme.ts` gains:

```ts
components: {
  // ...MuiButton, MuiButtonGroup and MuiTypography, unchanged
  MuiLink: {
    styleOverrides: {
      root: {
        variants: [
          {
            props: { color: 'primary' },
            style: ({ theme }) => ({
              color: (theme.vars || theme).palette.primary.dark,
              ...theme.applyStyles('dark', { color: (theme.vars || theme).palette.primary.main }),
            }),
          },
        ],
      },
    },
  },
},
```

**Why `primary.dark` in light mode:** `primary.main` has a ratio of 4.04 on `background.default` and 3.84 on `background.paper` in light mode, below the 4.5:1 that WCAG 2.2 AA asks for normal text. A link is usually body text, so it needs the higher ratio. `primary.dark` reaches 6.64 and 6.31. In dark mode `primary.main` already passes, at 4.87 and 4.60, while `primary.dark` fails, at 2.96, so dark mode keeps `primary.main`. The underline keeps MUI's translucent `primary.main`, because it's decoration and not text.

**`root` is kept as an object with `variants`.** A project's `root` object merges with it, and the color rule is kept. Two cases replace the rule, and the documentation must state both:

- A project's own `root.variants` array replaces the library's, because `deepmerge` doesn't merge arrays. A project that adds variants and wants the library's link color copies the rule above into its array.
- A project's function in `root` replaces the whole object, as described for Button in [0001](./0001-button.md#styling-hooks).

A project that changes `palette.primary` also changes the link color. Its `primary.dark` must still reach 4.5:1 in light mode, and its `primary.main` in dark mode.

## Accessibility

- **Semantics:** a native `<a>`. With `component`, the semantics are those of the element it renders. `component="button"` renders a `<button>`.
- **Keyboard:**
  - `Tab` moves focus to the link. An `<a>` without `href` isn't focusable.
  - `Enter` follows the link. `Space` doesn't, as with native links.
- **Naming:** the visible children. Avoid vague text such as "click here" (WCAG 2.4.4). A link with only an icon needs `aria-label`.
- **Focus:** shown by the theme's focus ring.
- **Telling links apart:** WCAG 1.4.1 says a link inside text can't rely on color alone. The default `underline="always"` covers this. With `hover` or `none`, a link inside text needs another visual cue, or a 3:1 contrast with the text around it plus a cue on hover and focus. The library's `primary.dark` reaches only 2.85:1 against `text.primary` in light mode, so inside text, keep the underline.
- **Contrast:** as listed under Styling hooks for `color="primary"`. Other `color` values follow the table in [0003](./0003-typography.md#accessibility).
- **New windows:** `target="_blank"` isn't announced. Say so in the text or with a visually hidden note where it matters. Modern browsers apply `noopener` to `_blank` links by default, so `rel="noopener"` is optional.

## Behavior and edge cases

- **`component="button"`:** renders a `<button>` with no `type`, so inside a form it submits the form. Pass `type="button"`. The documentation must state this. For most actions, Button with `variant="text"` is a better fit.
- **Router links:** the component passed to `component`, or set in the theme, must accept `ref` and spread its props onto the `<a>`. With the theme approach, `href` is the only link prop the consumer writes. Router-only props, such as `replace` or `state`, still need `component={RouterLink}` on the instance.
- **External links under a theme router:** the router receives every `href`, including `https://` and `mailto:` addresses. Most routers render those as plain `<a>`, but a project's `LinkBehavior` should check for them and render an `<a>` if its router doesn't.
- **Long URLs as text:** they don't break and can overflow narrow containers. Add `sx={{ overflowWrap: 'anywhere' }}` where that can happen.
- **Nested interactive content:** a Link can't contain a Button or another Link. That's invalid HTML.
- **Without the library theme:** Link renders with the surrounding MUI theme, in that theme's `primary.main`.
- **Server Components:** Link can be rendered from a Server Component, with the same limit as Button on function props. A theme `LinkBehavior` is a function, so the theme is created in a client component, as `CmThemeProvider` already requires.

## Acceptance criteria

- [x] Renders an `<a>` with the given `href`, named by its children.
- [x] `ref` reaches the DOM element.
- [x] `className`, `sx` and other props, such as `target`, `rel`, `data-*` and `aria-*`, reach the root element.
- [x] By default, the link has the `underlineAlways` class, and `variant="inherit"` takes the parent's font size.
- [x] `underline="hover"` and `underline="none"` add their classes.
- [x] `component={RouterLink} to="/x"` renders the router's link and passes it `to`.
- [x] Type check: `component={RouterLink} to="/x"` compiles, while an unknown prop or a missing required `to` fails.
- [x] A project-level `MuiLink.defaultProps.component` makes `<Link href="/x">` render that component, through `createCmTheme`.
- [x] A project-level `MuiButtonBase.defaultProps.LinkComponent` makes `<Button href="/x">` render that component, through `createCmTheme`.
- [x] Under the library theme, `color="primary"` uses `primary.dark` in light mode and `primary.main` in dark mode.
- [x] Under the library theme, `color="secondary"` keeps MUI's `secondary.main`.
- [x] Under the library theme, keyboard focus gives the link `Mui-focusVisible` and a solid outline.
- [x] `component="button"` renders a `<button>`, and with `type="button"` it doesn't submit a surrounding form.
- [x] A project-level `styleOverrides.root` object changes the look and keeps the library's link color.
- [x] An instance-level `sx` value overrides the theme.
- [x] Under another MUI theme, without `CmThemeProvider`, Link renders with that theme's `primary.main`.
- [x] Works with the keyboard as listed under Accessibility.
- [x] Storybook has a story for links inside text, one for each `underline` value, one for a router link, one for `component="button"` and one showing a theme override.
- [x] `Link` is exported from `src/index.ts` and added to the public API list in `tests/dist.test.ts`.

## Out of scope

- Props, variants or colors beyond those in MUI.
- Shipping a router adapter, or a dependency on any router.
- Telling internal and external links apart automatically, such as adding an icon or `target="_blank"` to external URLs.
- Announcing that a link opens a new window.
- A disabled state for links.
- Changing other palette colors to improve contrast. That belongs to a change in the architecture spec's tokens.

## Open questions

- **Link color:** this spec uses `primary.dark` in light mode to pass 4.5:1. If the design prefers the reference's `primary.main`, links in body text fail WCAG 2.2 AA in light mode, and the architecture spec would need to record that exception.
