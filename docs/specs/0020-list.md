# 0020: List

- **Status:** Implemented
- **Date:** 2026-11-10
- **Kind:** Composite
- **Depends on:** [0000](./0000-architecture.md), [0004](./0004-link.md)

## Purpose

Shows a vertical list of items built from data, such as the members of a team, the conversations in an inbox or the sections of a settings page. Each item can have a primary and a secondary line, an icon or an avatar, content at the end, and an action. Items can be links, buttons, or the selected item of a master-detail layout, and can hold nested items that expand and collapse.

MUI's `List` is only the `<ul>`. Each row needs `ListItem`, `ListItemButton`, `ListItemIcon` or `ListItemAvatar`, `ListItemText`, and for nested items `Collapse` and a second `List`, plus the selected state, the expanded state and the `aria-*` attributes that link them. This library's `List` takes an `items` array and assembles those parts.

List is also the base of Sidebar ([0026](./0026-sidebar.md)), and its item shape is the model for Menu's ([0021](./0021-menu.md)), so it sets how a data-driven list of links and buttons works in the library.

**Use it for:** a column of similar items that are read one after the other, such as people, files or notifications. A master-detail layout, where picking an item shows its details beside the list. A short navigation list inside a page, such as the sections of a settings page.

**Don't use it for:**

- Data with several attributes the user compares or sorts. Use Table ([0023](./0023-table.md)).
- Actions that open from a button. Use Menu ([0021](./0021-menu.md)).
- The app's main navigation. Use Sidebar ([0026](./0026-sidebar.md)) or Navbar ([0025](./0025-navbar.md)), which are built on this List or on the same link setup.
- Choosing a value in a form. Use Radio group, Select or Autocomplete.
- Thousands of items. List doesn't virtualize. See Behavior and edge cases.

## Usage

```tsx
import { Avatar, List } from '@cmotino/cm-web-components'
import type { ListItemData } from '@cmotino/cm-web-components'
import IconButton from '@mui/material/IconButton'

// Static rows.
<List
  aria-label="Team"
  items={members.map((member) => ({
    id: member.id,
    primary: member.name,
    secondary: member.role,
    avatar: <Avatar src={member.photoUrl} alt="" />,
    action: (
      <IconButton aria-label={`Remove ${member.name}`} onClick={() => remove(member.id)}>
        <DeleteIcon />
      </IconButton>
    ),
  }))}
/>

// Master-detail: one item is selected.
<List
  aria-label="Conversations"
  items={conversations.map((c) => ({ id: c.id, primary: c.subject, secondary: c.preview, end: c.time }))}
  value={selectedId}
  onChange={(_, id) => setSelectedId(id)}
/>

// Links with nested items. The router is set once in the theme, as in 0004.
const settings: ListItemData[] = [
  { id: 'profile', primary: 'Profile', icon: <PersonIcon />, href: '/settings/profile' },
  {
    id: 'billing',
    primary: 'Billing',
    icon: <CreditCardIcon />,
    children: [
      { id: 'invoices', primary: 'Invoices', href: '/settings/billing/invoices' },
      { id: 'plans', primary: 'Plans', href: '/settings/billing/plans' },
    ],
  },
]

<nav aria-label="Settings">
  <List subheader="Settings" items={settings} value={currentId} />
</nav>
```

## API

`List` is a component of this library, in `src/components/List/`, built on MUI's `List`, `ListItem`, `ListItemButton`, `ListItemIcon`, `ListItemAvatar`, `ListItemText`, `ListSubheader` and `Collapse`.

```ts
export { List } from './List.tsx'
export type { ListProps, ListItemData } from './List.types.ts'
```

| Prop | Type | Default | Required | Description |
| --- | --- | --- | --- | --- |
| `items` | `readonly ListItemData<Id>[]` | | Yes | The items, in display order |
| `value` | `Id \| null` | `undefined` | No | Controlled selected item. `null` means none is selected |
| `defaultValue` | `Id \| null` | `undefined` | No | Initial selected item when uncontrolled. See Selection |
| `onChange` | `(event: MouseEvent<HTMLElement>, value: Id) => void` | `undefined` | No | Called when the user activates an item that has no `children` |
| `expanded` | `readonly Id[]` | `undefined` | No | Controlled ids of the expanded parent items |
| `defaultExpanded` | `readonly Id[]` | The parents of the selected item | No | Initial expanded parents when uncontrolled |
| `onExpandedChange` | `(event: MouseEvent<HTMLElement>, expanded: Id[]) => void` | `undefined` | No | Called when the user expands or collapses a parent item |
| `subheader` | `ReactNode` | `undefined` | No | A heading at the top of the list, in MUI's `ListSubheader`. It also names the list when `aria-label` isn't set |
| `dense` | `boolean` | `false` | No | MUI's: smaller vertical padding on every item |
| `disablePadding` | `boolean` | `false` | No | MUI's: no padding above and below the list |
| `slotProps` | See below | `undefined` | No | Props for inner parts |

`List` also takes `sx`, `className`, `ref`, `aria-label`, `aria-labelledby` and other props of a `<ul>`, which reach the root `<ul>`, as the architecture spec requires. It's generic, as `List<Id extends string | number = string>`, and `Id` is inferred from `items`.

```ts
export interface ListProps<Id extends string | number = string>
  extends Omit<ComponentProps<'ul'>, 'onChange' | 'defaultValue' | 'children'> {
  items: readonly ListItemData<Id>[]
  value?: Id | null
  defaultValue?: Id | null
  onChange?: (event: MouseEvent<HTMLElement>, value: NoInfer<Id>) => void
  expanded?: readonly Id[]
  defaultExpanded?: readonly Id[]
  onExpandedChange?: (event: MouseEvent<HTMLElement>, expanded: NoInfer<Id>[]) => void
  subheader?: ReactNode
  dense?: boolean
  disablePadding?: boolean
  sx?: SxProps<Theme>
  slotProps?: {
    /** Every MUI `ListItem`, the `<li>`. */
    item?: Partial<Omit<MuiListItemProps, 'secondaryAction' | 'children'>>
    /** Every MUI `ListItemButton`, for interactive items. */
    itemButton?: Partial<Omit<MuiListItemButtonProps, 'href' | 'selected' | 'disabled' | 'onClick'>>
    /** Every MUI `ListItemIcon`. */
    itemIcon?: Partial<MuiListItemIconProps>
    /** Every MUI `ListItemAvatar`. */
    itemAvatar?: Partial<MuiListItemAvatarProps>
    /** Every MUI `ListItemText`. Reaches its `primary` and `secondary` slots through its own `slotProps`. */
    itemText?: Partial<Omit<MuiListItemTextProps, 'primary' | 'secondary'>>
    /** MUI's `ListSubheader`. */
    subheader?: Partial<MuiListSubheaderProps>
    /** Every nested `<ul>` of a parent item. */
    nested?: Partial<MuiListProps>
  }
}
```

### How an item renders

| Item | Renders as | Activating it |
| --- | --- | --- |
| No `href`, `onClick` or `children`, and the List has no `onChange`, `value` or `defaultValue` | A static `<li>` with its content | Nothing |
| `href` | A link in the `<li>`, through `MuiButtonBase.defaultProps.LinkComponent` | Calls `item.onClick`, then `onChange`, then follows the link |
| `onClick`, or the List has `onChange`, `value` or `defaultValue` | A `<div role="button">` in the `<li>` (MUI's `ListItemButton`) | Calls `item.onClick`, then selects it and calls `onChange` |
| `children` | A button with an expand icon at the end, and the nested `<ul>` inside the same `<li>`, in MUI's `Collapse` | Expands or collapses it, and calls `onExpandedChange`. It's never selected and doesn't call `onChange` |

Links work with a project's router as set up in [0004](./0004-link.md#usage). This is the same setup Tabs uses for link tabs ([0019](./0019-tabs.md#api)).

`action` is rendered in MUI's `secondaryAction` slot, outside the button, so a button inside it is never nested in another interactive element. `end` is rendered inside the item, after the text, and is part of the button's accessible name, so it must not be interactive.

### Selection

- A List tracks a selected item only when `value` or `defaultValue` is passed. Pass `defaultValue={null}` for a selectable List that starts with nothing selected.
- Uncontrolled, activating an item without `children` selects it. A controlled List shows whatever `value` the consumer passes, which is how a list of links shows the current route.
- The selected item gets MUI's `selected` style and `aria-current`: `"page"` for a link, `"true"` otherwise. See Accessibility.
- If the selected item is removed from `items`, an uncontrolled List selects nothing, without calling `onChange`.

### Expansion

- Uncontrolled, the parents of the selected item start expanded, so the current page is visible. A `defaultExpanded` replaces this.
- A parent's toggle has `aria-expanded` and `aria-controls` pointing at its nested `<ul>`. Ids are built from one React `useId` and the item's position, so item ids can be any string.
- Nested items are indented by one `theme.spacing(2)` per level. Any depth works, but more than two levels is hard to scan.
- A collapsed nested `<ul>` stays in the DOM inside `Collapse`, which hides it with `visibility: hidden`, so its links aren't reachable with `Tab` or by screen readers.

### Theme key

List reads its props through `useThemeProps({ props, name: 'CmList' })`, and styles its parts with MUI's `styled`, with `name: 'CmList'` and the slots `root`, `item`, `itemButton` and `nested`. The class names `CmList-root`, `CmList-item`, `CmList-itemButton` and `CmList-nested` are added to those elements. The key is declared through module augmentation in `List.types.ts`, as [0019](./0019-tabs.md#theme-key) does for `CmTabs`.

### Exceptions to the architecture spec

None. The root is the `<ul>`, so `aria-label` and the other props reach it.

`List.tsx` starts with `'use client'`, because it calls `useId` and keeps state, and is added to `tests/dist.test.ts`.

## Data shapes

```ts
interface ListItemDataBase<Id extends string | number> {
  /** Unique within the whole tree of `items`. Used as the React key, the value, and reported by `onChange`. */
  id: Id
  /** The main line. It's also the item's accessible name, with `secondary` and `end`. */
  primary: ReactNode
  /** A second line, in `text.secondary`. */
  secondary?: ReactNode
  /** Shown before the text, in MUI's `ListItemIcon`. Use `icon` or `avatar`, not both. */
  icon?: ReactNode
  /** Shown before the text, in MUI's `ListItemAvatar`. */
  avatar?: ReactNode
  /** Non-interactive content after the text, inside the item, such as a count or a time. */
  end?: ReactNode
  /** An interactive element at the end, outside the item's button, such as an icon button. */
  action?: ReactNode
  /**
   * Shown but not interactive.
   * @default false
   */
  disabled?: boolean
  /**
   * Draws a `divider` line below the item.
   * @default false
   */
  divider?: boolean
  /** Called when the item is activated, before `onChange`. */
  onClick?: (event: MouseEvent<HTMLElement>) => void
}

export type ListItemData<Id extends string | number = string> = ListItemDataBase<Id> &
  (
    | { /** Makes the item a link. */ href: string; children?: never }
    | { /** Nested items, shown when the item is expanded. */ children: readonly ListItemData<Id>[]; href?: never }
    | { href?: never; children?: never }
  )
```

An item can have `href` or `children`, not both, so a parent that toggles can't also be a link.

## Variants and states

| Variant or state | Behavior or appearance |
| --- | --- |
| Default | MUI's list: items 16px from the sides, the primary line in `body1` and `text.primary`, the secondary line in `body2` and `text.secondary`, 8px of padding above and below the list |
| `dense` | MUI's dense items, with less vertical padding |
| Hover, interactive items | `action.hover` background |
| Keyboard focus | The theme's focus ring around the item's button or link, from [0001](./0001-button.md#styling-hooks) |
| Selected | MUI's selected background, `primary.main` at `action.selectedOpacity`, and a 3px `primary.main` bar on the start edge. See Styling hooks |
| Disabled | MUI's: the item at `action.disabledOpacity`, not interactive |
| Parent, collapsed and expanded | A chevron at the end, pointing down when collapsed and up when expanded. Nested items slide open with MUI's `Collapse` |
| With `subheader` | MUI's subheader, in `text.secondary`, sticky at the top of a scrolling list |
| With `divider` | A 1px `divider` line below the item |
| Empty | `items={[]}`: an empty `<ul>`, with the subheader if set |

## Styling hooks

- **Theme keys:** `components.CmList`, with the slots `root`, `item`, `itemButton` and `nested`, and default props for every List prop. The parts also use `MuiList`, `MuiListItem`, `MuiListItemButton`, `MuiListItemIcon`, `MuiListItemAvatar`, `MuiListItemText`, `MuiListSubheader` and `MuiCollapse`.
- **Slots:** `item`, `itemButton`, `itemIcon`, `itemAvatar`, `itemText`, `subheader` and `nested`, as typed under API. The root is reached with `sx` and `className`.
- **Default look:** MUI's list, with colors, font and spacing from the library's design tokens. List's own `itemButton` style adds the selected bar, drawn with a `::before` pseudo-element at `inset-inline-start: 0`, so it follows the text direction. The chevron is made with `createSvgIcon` from `@mui/material/utils`, as the architecture spec requires. The style lives in `CmList`, not in `MuiListItemButton`, so plain MUI lists under the library theme don't change.

**Why the bar:** the selected background differs from the page by much less than 3:1, so on its own it doesn't meet WCAG 2.2 AA 1.4.11 for showing the state. The bar is `primary.main`, at 3.66 light and 4.29 dark against the selected background, which meets 3:1. The text keeps `text.primary`, at 16 or more on the selected background in both schemes.

## Accessibility

- **Semantics:** a `<ul>` with one `<li>` per item. Interactive items are a `<div role="button">` or an `<a>` inside the `<li>`. A parent's nested items are a `<ul>` inside its `<li>`.
- **Selected item:** `aria-current="page"` on a link, `aria-current="true"` on a button. `aria-selected` isn't valid on a button or a link, and a `listbox` would need arrow-key handling, which is out of scope. See [Open questions](#open-questions).
- **Keyboard:**
  - `Tab` and `Shift+Tab` move between interactive items and the elements in `action`, in order. Every interactive item is in the tab order.
  - `Enter` activates an item. `Space` activates a button, but not a link, as in the browser.
  - On a parent, `Enter` and `Space` expand or collapse it.
  - Arrow keys don't move between items. That's out of scope.
- **Naming:** the list is named by `aria-label` or `aria-labelledby`. Without either, and with a `subheader`, the list gets `aria-labelledby` pointing at the subheader. Each item is named by its text content: `primary`, `secondary` and `end`. An item with only an icon has no name. That's out of scope.
- **Focus:** expanding or collapsing a parent keeps focus on it. A nested item that's collapsed can't be focused.
- **Contrast:** as described under Styling hooks. Secondary text is `text.secondary`, at 7.15 or more on both backgrounds and both schemes, and at 6.14 or more on the selected background.

## Behavior and edge cases

- **Duplicate ids:** React logs key warnings, and both items show as selected. Ids must be unique across nesting levels.
- **A `value` that isn't in `items`:** no item is selected, without a warning, so a route with no item, such as `/404`, works.
- **A selected item inside a collapsed parent:** stays selected but hidden. A controlled `expanded` is the consumer's to update. Uncontrolled, the parents expand only when the List mounts.
- **Long text:** wraps, as in MUI. `slotProps.itemText.slotProps.primary.noWrap` cuts it off with an ellipsis instead.
- **`action` and `end` together:** `end` sits before the action. MUI reserves 48px for `secondaryAction` on the item's end side, so a wider action overlaps the text. Keep it to one icon button.
- **Many items:** List renders every item, and every nested item, even collapsed. A few hundred items are fine. For more, paginate or filter before passing `items`. Virtualization is out of scope.
- **A link with `onClick`:** both run. `event.preventDefault()` in `onClick` stops the navigation.
- **A disabled link:** MUI renders the `<a>` with `aria-disabled="true"` and `tabIndex={-1}`, and doesn't call `onClick`. The `href` stays, so a project's router `LinkComponent` must not navigate when `aria-disabled` is set.
- **Narrow screens:** the list fills its container. Nothing changes by breakpoint.
- **Without the library theme:** List renders with the surrounding MUI theme. The selected bar uses that theme's `primary.main`.
- **Server Components:** List is a client component. `items` can come from a Server Component, as long as each `ReactNode` is serializable or a Server Component element. `onClick` can't cross that boundary.

## Acceptance criteria

- [ ] Renders a `list` named by `aria-label`, with one `listitem` for each item, in order, showing `primary`, `secondary`, `icon`, `avatar`, `end` and `action`.
- [ ] Without `aria-label` or `aria-labelledby`, a List with a `subheader` is named by it.
- [ ] An item with `href` renders a link through the theme's `MuiButtonBase.defaultProps.LinkComponent`.
- [ ] An item with `onClick` renders a button, and clicking it calls `onClick` and `onChange` with the event and the item's `id`, in that order.
- [ ] A static List renders no buttons or links.
- [ ] Works controlled with `value` and `onChange`, and uncontrolled with `defaultValue`, without React or MUI warnings. Without `value` or `defaultValue`, activating an item selects nothing.
- [ ] The selected item has the selected class and `aria-current`: `"page"` on a link and `"true"` on a button.
- [ ] A parent item toggles its nested list on click, `Enter` and `Space`, with `aria-expanded` and `aria-controls` kept in sync, and calls `onExpandedChange` with the new ids. It never calls `onChange`.
- [ ] Uncontrolled, the parents of the selected item start expanded. `defaultExpanded` and controlled `expanded` replace that.
- [ ] Links inside a collapsed parent can't be reached with `Tab`.
- [ ] A disabled item can't be activated, and isn't in the tab order.
- [ ] `dense`, `disablePadding` and `divider` reach MUI's components.
- [ ] `ref` reaches the root `<ul>`, and `className`, `sx` and other props, such as `data-*`, reach it too.
- [ ] Every entry in `slotProps` reaches its elements.
- [ ] The root, items, item buttons and nested lists have the `CmList-root`, `CmList-item`, `CmList-itemButton` and `CmList-nested` classes.
- [ ] Type check: `Id` is inferred from `items`, `onChange` receives that type, and an item with both `href` and `children` fails.
- [ ] Under the library theme, the selected item shows the `primary.main` bar on the start edge, on the right in a right-to-left layout.
- [ ] A project-level `CmList.defaultProps.dense` of `true` applies to every List.
- [ ] A project-level `CmList` `styleOverrides.itemButton` object changes the item buttons.
- [ ] Type check: `createCmTheme({ components: { CmList: { defaultProps: { dense: true }, styleOverrides: { nested: { paddingLeft: 0 } } } } })` compiles, and an unknown slot name fails.
- [ ] An instance-level `sx` value overrides the theme.
- [ ] Under another MUI theme, without `CmThemeProvider`, List renders with that theme.
- [ ] Works with the keyboard as listed under Accessibility.
- [ ] Storybook has a story for static, link, selectable, nested, dense, with avatars and actions, with a subheader, empty, and one showing a theme override.
- [ ] `List`, `ListProps` and `ListItemData` are exported from `src/index.ts`, and `List` is added to the public API and `'use client'` lists in `tests/dist.test.ts`.

## Out of scope

- Arrow-key navigation between items, and `listbox` or `tree` semantics.
- Selecting more than one item, or checkboxes in items.
- Dragging items to reorder them.
- Virtualization of long lists.
- Loading more items when the user scrolls to the end.
- Items with only an icon and no visible text.
- Exporting MUI's `ListItem` and its parts for consumers who assemble lists themselves. They can import them from MUI.

## Open questions

- **Selection semantics:** a master-detail List uses buttons with `aria-current="true"`. A `listbox` with `aria-selected` and arrow keys is closer to what screen reader users expect for a selectable list, but needs roving focus. Decide whether that's worth a later version.
- **Nested items in List or in Sidebar:** nesting is here so Sidebar can reuse it. If no consumer needs nested items outside Sidebar, it could move there, keeping List smaller.
