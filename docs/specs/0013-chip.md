# 0013: Chip

- **Status:** Implemented
- **Date:** 2026-11-09
- **Kind:** Simple
- **Depends on:** [0000](./0000-architecture.md), [0011](./0011-avatar.md)

## Purpose

Gives projects a compact element for a tag, a status, a filter or a selected value, which can show an icon or an avatar, be clicked and be removed. MUI's `Chip` already covers the behavior, including the delete icon and the `Backspace` and `Delete` keys, so this library re-exports it and changes two colors that fail WCAG 2.2 AA contrast under the library theme: the delete icon, and initials in an avatar. It also takes disabled deletable chips out of the tab order, which MUI doesn't do. Autocomplete, next on the [roadmap](./roadmap.md), shows its selected values as these chips.

**Use it for:** tags on an item, a status in a table such as "Paid" or "Draft", filters that can be turned on and off, and selected values that can be removed, such as recipients of an email.

**Don't use it for:**

- A main action, such as "Save". Use Button.
- Choosing one option out of a few, where the choice is a form value. Use Radio group, or Button group for a toolbar.
- A count on an icon. Use Badge.
- Navigation between sections. Use Tabs or Link, which are on the [roadmap](./roadmap.md).

## Usage

```tsx
import { Avatar, Chip } from '@cmotino/cm-web-components'
import DoneIcon from '@mui/icons-material/Done'

<Chip label="Draft" />

<Chip label="Paid" color="success" variant="outlined" />

<Chip
  label="Only open"
  icon={onlyOpen ? <DoneIcon /> : undefined}
  variant={onlyOpen ? 'filled' : 'outlined'}
  onClick={() => setOnlyOpen(!onlyOpen)}
  aria-pressed={onlyOpen}
/>

<Chip
  label={user.name}
  avatar={<Avatar src={user.photoUrl} alt="" />}
  onDelete={() => removeRecipient(user.id)}
/>

<Chip label="Docs" component="a" href="/docs" clickable />
```

## API

`Chip` is MUI's `Chip`, re-exported from `src/components/Chip/index.ts`. Every MUI prop works as documented by MUI 9. No props are added or removed.

```ts
export { default as Chip } from '@mui/material/Chip'
export type { ChipProps } from '@mui/material/Chip'
```

| Prop | Type | Default | Required | Description |
| --- | --- | --- | --- | --- |
| `skipFocusWhenDisabled` | `boolean` | `true` under the library theme, `false` otherwise | No | The only default that differs from MUI. It's set in the theme, not in the component. See Styling hooks |

The props a consumer uses most are `label`, `variant`, `color`, `size`, `icon`, `avatar`, `onClick`, `clickable`, `onDelete`, `deleteIcon`, `disabled` and `slotProps`. MUI's other defaults are kept, including `variant="filled"`, `color="default"` and `size="medium"`. `children` isn't accepted, as in MUI. The text goes in `label`.

**Why a re-export and not a wrapper:** the same reasons as Button in [0001](./0001-button.md#api). A wrapper typed as `(props: ChipProps) => ...` would break `component="a"` with `href`, and MUI's `Chip` has no logic for this library to add.

### Exceptions to the architecture spec

| Rule | Exception | Reason |
| --- | --- | --- |
| Section 2: icons are passed as `ReactNode` | `icon`, `avatar` and `deleteIcon` are `ReactElement` | MUI's `Chip` clones them to add its class names, so it needs an element, not any node |
| Section 6: `Chip.tsx` and `Chip.types.ts` | Neither file exists. The folder holds `index.ts`, `Chip.test.tsx` and `Chip.stories.tsx` | There is no component code or type of our own to put in them |

No `'use client'` directive is needed, because this module has no hooks and MUI's `Chip` module carries its own.

## Variants and states

| Variant or state | Behavior or appearance |
| --- | --- |
| Default | A 32px pill, 16px radius, with `text.primary` text on `action.selected`, as in MUI |
| `variant="outlined"` | A transparent chip with a 1px border in `grey[400]` in light mode and `grey[700]` in dark mode, as in MUI |
| `color` | `primary`, `secondary`, `info`, `success`, `warning` or `error`, as in MUI |
| `size="small"` | 24px tall, as in MUI |
| With `icon` | The icon before the label, in `grey[700]` in light mode and `grey[300]` in dark mode on a default chip, as in MUI |
| With `avatar` | A 24px avatar before the label. On a default chip, the initials are `common.white` on the avatar's `grey[500]` |
| Clickable | Rendered on MUI's `ButtonBase`, with a hover background and a ripple, as in MUI |
| Deletable | A delete icon after the label. On a default chip it's `text.secondary`, and `text.primary` on hover |
| Keyboard focus | The theme's focus ring around the chip, from [0001](./0001-button.md#styling-hooks), as MUI draws it on `ButtonBase` when `focusVisible` is on |
| Disabled | Dimmed, can't be clicked or deleted, and out of the tab order. See Styling hooks |
| Long label | Cut off with an ellipsis. See Behavior and edge cases |

## Styling hooks

- **Theme key:** `components.MuiChip`. New variants, colors and sizes use MUI's `ChipPropsVariantOverrides`, `ChipPropsColorOverrides` and `ChipPropsSizeOverrides`, augmented on `@mui/material/Chip`.
- **Slots:** `root` and `label`, as in MUI. The icon, avatar and delete icon are elements passed as props, and are reached with the `icon`, `avatar` and `deleteIcon` override keys.
- **Default look:** MUI's chip, with colors from the library's design tokens, the two fixes below for default-colored chips, and one default prop for disabled chips. `src/theme/defaultTheme.ts` gains:

```ts
components: {
  // ...earlier components, unchanged
  MuiChip: {
    defaultProps: { skipFocusWhenDisabled: true },
    styleOverrides: {
      deleteIcon: ({ theme, ownerState }) =>
        ownerState.color === 'default'
          ? {
              color: (theme.vars || theme).palette.text.secondary,
              '&:hover': { color: (theme.vars || theme).palette.text.primary },
            }
          : {},
      avatar: ({ theme, ownerState }) =>
        ownerState.color === 'default'
          ? { color: (theme.vars || theme).palette.common.white }
          : {},
    },
  },
},
```

**Why the delete icon:** MUI draws it in `text.primary` at 26% opacity, and 40% on hover. On a default chip under the library theme that's 1.81:1 in light mode and 2.37:1 in dark mode, below the 3:1 that WCAG 2.2 AA asks for a control (1.4.11). `text.secondary` gives 6.96 and 6.33.

**Why the avatar:** MUI sets the text of a chip's avatar to `grey[700]` in light mode and `grey[300]` in dark mode. On the `grey[500]` background from [0011](./0011-avatar.md#styling-hooks) that's 1.86:1 and 3.56:1, below 4.5:1 for 12px initials. White gives 5.93. Avatars with a working image aren't affected.

**Why `skipFocusWhenDisabled`:** MUI disables its `ButtonBase` only when a chip is clickable. A disabled chip with `onDelete` and no `onClick` keeps `tabindex="0"`, so `Tab` reaches it and `Backspace` or `Delete` still calls `onDelete`. Only clicks are blocked, by `pointer-events: none`. The default gives disabled chips `tabindex="-1"`. Clickable chips already get it from `ButtonBase`. A chip that code focuses directly still deletes on `Backspace`, as listed under Behavior and edge cases. A project that wants MUI's behavior passes `createCmTheme({ components: { MuiChip: { defaultProps: { skipFocusWhenDisabled: false } } } })`.

**Only default-colored chips change.** Colored chips draw the delete icon and avatar from their palette color, and their contrast depends on the palette. See [Open questions](#open-questions).

**These rules apply to every MUI `Chip`** under the library theme, including one used directly from MUI and the tags in MUI's `Autocomplete`. A project's own `deleteIcon` or `avatar` in `MuiChip.styleOverrides` replaces the library's, because `deepmerge` doesn't merge functions. The documentation must state this.

## Accessibility

- **Semantics:**
  - A chip without `onClick`, `clickable` or `onDelete` is a `<div>` with no role, read as its label.
  - A clickable or deletable chip is a `<div role="button" tabindex="0">`, from MUI's `ButtonBase`. With `component="a"` and `href`, it's a link.
  - A chip used as a toggle, such as a filter, passes `aria-pressed`, as in the third example.
- **Keyboard:**
  - `Tab` moves focus to a clickable or deletable chip.
  - `Enter` and `Space` call `onClick`.
  - `Backspace` and `Delete` call `onDelete`.
  - The delete icon can't take focus on its own. Keyboard users delete with the keys above.
- **Naming:** the `label`. The delete icon has no name and isn't announced, so a screen reader user doesn't learn that `Backspace` removes the chip. A list of removable chips should say so nearby, such as in a field's helper text. An avatar beside the label gets `alt=""`, because the label already names the person.
- **Focus:** shown by the theme's focus ring. After a chip is deleted, focus is lost unless the consumer moves it, such as to the next chip or to the field the chips belong to.
- **Contrast:** the label meets 4.5:1 on default chips. The default chip's background is 1.08:1 against the light background and 1.21:1 against the dark one, which is allowed because the label identifies the chip, but the chip barely shows as a shape. See [Open questions](#open-questions).

## Behavior and edge cases

- **Long labels:** the label has `white-space: nowrap` and an ellipsis, so the chip doesn't grow past its container. A consumer sets a `maxWidth` with `sx`, and gives the full text another way, such as a Tooltip, which is on the [roadmap](./roadmap.md).
- **Many chips:** they're inline elements and wrap with the text. A layout with gaps needs a flex container from the consumer.
- **Deleting:** Chip reports `onDelete` and doesn't remove itself. The consumer removes the item from its data.
- **A chip that's both clickable and deletable:** clicking the delete icon calls only `onDelete`, because MUI stops the event.
- **Disabled:** `pointer-events: none`, and `tabindex="-1"` from the library's `skipFocusWhenDisabled` default. A disabled clickable chip ignores `Enter`, `Space`, `Backspace` and `Delete` even when focused from code. A disabled chip with only `onDelete` still calls it on `Backspace` or `Delete` if code focuses it, so a consumer who focuses chips from code doesn't focus disabled ones.
- **Without the library theme:** Chip renders with the surrounding MUI theme and its colors. MUI's own `Chip` used directly under the library theme gets the library look.
- **Server Components:** Chip can be rendered from a Server Component, but function props such as `onClick` and `onDelete` can't cross that boundary.

## Acceptance criteria

- [ ] Renders the `label`.
- [ ] With `icon` or `avatar`, renders it before the label.
- [ ] With `onClick`, renders an element with `role="button"`, and clicking it or pressing `Enter` calls `onClick`.
- [ ] With `onDelete`, renders the delete icon, and clicking it or pressing `Backspace` or `Delete` on the focused chip calls `onDelete`.
- [ ] Clicking the delete icon of a clickable chip doesn't call `onClick`.
- [ ] `disabled` stops `onClick` and `onDelete`. Under the library theme, a disabled chip with only `onDelete` isn't reached with `Tab`.
- [ ] `component="a"` with `href` renders a link.
- [ ] `ref` reaches the root element.
- [ ] `className`, `sx` and other props, such as `data-*` and `aria-*`, reach the root element.
- [ ] Each slot in `slotProps` reaches its element.
- [ ] Under the library theme, the delete icon of a default chip is `text.secondary`, and `text.primary` on hover.
- [ ] Under the library theme, an avatar with initials in a default chip has `common.white` text.
- [ ] Under the library theme, colored chips keep MUI's delete icon and avatar colors.
- [ ] Under the library theme, keyboard focus shows the focus ring.
- [ ] A project-level `MuiChip.defaultProps.skipFocusWhenDisabled` of `false` restores MUI's focus on disabled deletable chips.
- [ ] A project-level `MuiChip` `styleOverrides.root` object changes the look and keeps the library's delete icon and avatar colors.
- [ ] An instance-level `sx` value overrides the theme.
- [ ] Under another MUI theme, without `CmThemeProvider`, Chip renders with that theme.
- [ ] Works with the keyboard as listed under Accessibility.
- [ ] Storybook has a story for every variant and state, one for filter chips that toggle, one for removable recipients with avatars, and one showing a theme override.
- [ ] `Chip` is exported from `src/index.ts` and added to the public API list in `tests/dist.test.ts`.

## Out of scope

- A chip group or chip input, which manages a list of chips, selection or adding new ones. Autocomplete covers selected values.
- A focusable delete button inside the chip.
- Moving focus after a chip is deleted.
- A `selected` prop for filter chips. Consumers use `variant`, `icon` and `aria-pressed`, as in the third example.
- Labels that wrap onto several lines.

## Open questions

- **Default chip background:** `action.selected` from the reference tokens is 1.08:1 against the light background, so a default chip looks like plain text in light mode. Confirm that the design accepts it, or give default chips a visible background or border, which the reference theme doesn't define.
- **Colored chips:** the palette sets their contrast. `primary.contrastText` on `primary.main` is 3.65:1 and `info.contrastText` on `info.main` is 2.36:1 in light mode, below 4.5:1 for the label, the same problem noted for Badge in [0012](./0012-badge.md#open-questions). On colored chips the delete icon is drawn at 70% opacity, which gives 2.52:1 on a filled `primary` chip. On outlined chips the label and delete icon use the `main` color, which is below 3:1 against the background for `success` and `info` in both schemes and for `error` in dark mode. Decide whether to fix these in the palette, through the architecture spec, or to limit which colors Chip documents.

The rows from the source were rechecked on implementing, and the rendered rows are covered by `Chip.test.tsx` in jsdom. Recheck when upgrading MUI.
