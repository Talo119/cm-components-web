# 0021: Menu

- **Status:** Implemented
- **Date:** 2026-11-10
- **Kind:** Composite
- **Depends on:** [0000](./0000-architecture.md), [0001](./0001-button.md), [0004](./0004-link.md), [0020](./0020-list.md)

## Purpose

Opens a short list of actions or links from a button, such as "Edit", "Duplicate" and "Delete" behind a "More options" icon button, or "Profile" and "Sign out" behind a user's avatar. MUI's `Menu` needs the consumer to keep the anchor element and the open state, close the menu after each choice, put `aria-haspopup`, `aria-expanded` and `aria-controls` on the button, and assemble each `MenuItem` with its icon and text. This library's `Menu` takes the button as `trigger` and the choices as `items`, and does all of that.

Menu's items follow List's item shape ([0020](./0020-list.md#data-shapes)): `id`, a label, an `icon`, `disabled`, `divider`, `onClick` and `href`, so moving between the two is easy. It's built on MUI's `Menu`, which is itself built on MUI's `List`.

**Use it for:** actions about one thing, such as a row of a table or a card, behind an icon button. A few choices that don't fit as buttons, such as "Export as CSV" and "Export as PDF". The account menu in Navbar ([0025](./0025-navbar.md)).

**Don't use it for:**

- Choosing a value in a form. Use Select, which shows the chosen value.
- A main action. Put it on a Button, where users see it without opening anything.
- Long lists or lists with search. Use Autocomplete.
- Two or three actions that fit on screen. Show them as Buttons or a Button group.
- Content other than choices, such as a form or a card. That's a popover, which isn't on the [roadmap](./roadmap.md).

## Usage

```tsx
import { Button, Menu } from '@cmotino/cm-web-components'
import IconButton from '@mui/material/IconButton'

<Menu
  trigger={<Button endIcon={<ExpandMoreIcon />}>Export</Button>}
  items={[
    { id: 'csv', label: 'CSV' },
    { id: 'pdf', label: 'PDF' },
  ]}
  onItemClick={(_, id) => exportAs(id)}
/>

<Menu
  trigger={
    <IconButton aria-label={`Options for ${project.name}`}>
      <MoreVertIcon />
    </IconButton>
  }
  placement="bottom-end"
  items={[
    { id: 'edit', label: 'Edit', icon: <EditIcon />, href: `/projects/${project.id}/edit` },
    { id: 'duplicate', label: 'Duplicate', icon: <ContentCopyIcon />, onClick: () => duplicate(project.id) },
    { id: 'archive', label: 'Archive', icon: <ArchiveIcon />, divider: true, onClick: () => archive(project.id) },
    { id: 'delete', label: 'Delete', icon: <DeleteIcon />, disabled: !canDelete, onClick: () => confirmDelete(project.id) },
  ]}
/>
```

## API

`Menu` is a component of this library, in `src/components/Menu/`, built on MUI's `Menu`, `MenuItem`, `ListItemIcon` and `ListItemText`.

```ts
export { Menu } from './Menu.tsx'
export type { MenuProps, MenuItemData } from './Menu.types.ts'
```

| Prop | Type | Default | Required | Description |
| --- | --- | --- | --- | --- |
| `trigger` | `ReactElement` | | Yes | The button that opens the menu. See Trigger |
| `items` | `readonly MenuItemData<Id>[]` | | Yes | The choices, in display order |
| `onItemClick` | `(event: MouseEvent<HTMLElement>, id: Id) => void` | `undefined` | No | Called when the user chooses an item, after the item's own `onClick` |
| `open` | `boolean` | `undefined` | No | Controlled open state |
| `defaultOpen` | `boolean` | `false` | No | Initial open state when uncontrolled |
| `onOpenChange` | `(event: SyntheticEvent \| Event, open: boolean) => void` | `undefined` | No | Called when the menu asks to open or close |
| `placement` | `'bottom-start' \| 'bottom-end' \| 'top-start' \| 'top-end'` | `'bottom-start'` | No | Where the menu opens, relative to the trigger. `start` and `end` follow the text direction |
| `dense` | `boolean` | `false` | No | MUI's: smaller items |
| `slotProps` | See below | `undefined` | No | Props for inner parts |

`Menu` also takes `sx`, `className` and `ref`. See Exceptions. It's generic, as `Menu<Id extends string | number = string>`, and `Id` is inferred from `items`.

```ts
export interface MenuProps<Id extends string | number = string> {
  trigger: ReactElement
  items: readonly MenuItemData<Id>[]
  onItemClick?: (event: MouseEvent<HTMLElement>, id: NoInfer<Id>) => void
  open?: boolean
  defaultOpen?: boolean
  onOpenChange?: (event: SyntheticEvent | Event, open: boolean) => void
  placement?: 'bottom-start' | 'bottom-end' | 'top-start' | 'top-end'
  dense?: boolean
  className?: string
  sx?: SxProps<Theme>
  ref?: Ref<HTMLDivElement>
  slotProps?: {
    /** MUI's `Menu`. Reaches its other props, such as `anchorOrigin`, and its own slots. */
    menu?: Partial<Omit<MuiMenuProps, 'open' | 'anchorEl' | 'onClose' | 'children'>>
    /** Every MUI `MenuItem`. */
    item?: Partial<Omit<MuiMenuItemProps, 'onClick' | 'disabled' | 'divider' | 'href'>>
    /** Every MUI `ListItemIcon`. */
    itemIcon?: Partial<MuiListItemIconProps>
    /** Every MUI `ListItemText`. */
    itemText?: Partial<Omit<MuiListItemTextProps, 'primary'>>
  }
}
```

### Trigger

`trigger` is cloned with these props, composed with its own:

| Prop | Value |
| --- | --- |
| `id` | Its own `id`, or one from `useId` |
| `onClick` | Its own `onClick`, then opens or closes the menu, unless the event's default was prevented |
| `onKeyDown` | Its own, then `ArrowDown` opens the menu on the first item and `ArrowUp` on the last |
| `aria-haspopup` | `"menu"` |
| `aria-expanded` | `"true"` while open, otherwise not set |
| `aria-controls` | The menu's id while open, otherwise not set |
| `ref` | Merged with its own `ref`, so the menu can anchor to it |

The trigger must be a single element that renders a focusable DOM element and accepts these props, such as Button, MUI's `IconButton`, or a `<button>`. React 19 passes `ref` as a normal prop, so cloning keeps the consumer's `ref`.

### Choosing an item

Clicking an enabled item, or pressing `Enter` or `Space` on it, calls `item.onClick(event)`, then `onItemClick(event, id)`, then closes the menu. An item with `href` is a link, through `MuiButtonBase.defaultProps.LinkComponent`, as set up in [0004](./0004-link.md#usage), and still has `role="menuitem"`.

**Placement:** `bottom-start` maps to MUI's `anchorOrigin={{ vertical: 'bottom', horizontal: 'left' }}` and `transformOrigin={{ vertical: 'top', horizontal: 'left' }}`, swapped in right-to-left layouts. MUI 9.5 already opens below the anchor, but Menu sets both origins itself, so every `placement` works the same way. `slotProps.menu.anchorOrigin` and `transformOrigin` win over `placement`.

**Variant:** Menu passes `variant="menu"` to MUI, because its items have no selected state, so focus always starts on the first enabled item.

### Theme key

Menu reads its props through `useThemeProps({ props, name: 'CmMenu' })`, and styles its parts with MUI's `styled`, with `name: 'CmMenu'` and the slots `root`, `paper` and `item`. `root` is MUI's `Menu` root, the full-screen layer in a portal. `paper` is the visible surface. The class names `CmMenu-root`, `CmMenu-paper` and `CmMenu-item` are added to those elements. The key is declared through module augmentation in `Menu.types.ts`, as [0019](./0019-tabs.md#theme-key) does for `CmTabs`.

### Exceptions to the architecture spec

| Rule | Exception | Reason |
| --- | --- | --- |
| Section 2: `sx` and `className` reach the root | They reach the menu's paper | Menu has no element of its own around the trigger, and MUI's root is a full-screen layer, so the paper is the element a consumer means to style |
| Section 2: `ref` reaches the root | It reaches the paper `<div>` | Same reason |
| Section 2: remaining props reach the root | Menu takes no other props at the top level | They'd be ambiguous between the trigger and the menu. The trigger takes its own, and the menu takes them through `slotProps.menu` |

`Menu.tsx` starts with `'use client'`, because it calls `useId` and keeps state, and is added to `tests/dist.test.ts`.

## Data shapes

```ts
interface MenuItemDataBase<Id extends string | number> {
  /** Unique within `items`. Used as the React key and reported by `onItemClick`. */
  id: Id
  /** The item's visible text. It's also the item's accessible name. */
  label: ReactNode
  /** Shown before the label, in MUI's `ListItemIcon`. */
  icon?: ReactNode
  /** Shown at the end in `text.secondary`, such as a keyboard shortcut. Part of the accessible name. */
  secondary?: ReactNode
  /**
   * Shown but not selectable, and skipped by the arrow keys.
   * @default false
   */
  disabled?: boolean
  /**
   * Draws a `divider` line below the item, to separate groups.
   * @default false
   */
  divider?: boolean
  /**
   * Marks a link as the current page, with `aria-current="page"` and MUI's
   * selected background. Navbar uses it in its menus.
   * @default false
   */
  current?: boolean
  /** Called when the item is chosen, before `onItemClick`. */
  onClick?: (event: MouseEvent<HTMLElement>) => void
}

export type MenuItemData<Id extends string | number = string> = MenuItemDataBase<Id> & {
  /** Makes the item a link. */
  href?: string
}
```

## Variants and states

| Variant or state | Behavior or appearance |
| --- | --- |
| Closed | Only the trigger is rendered. The menu isn't in the DOM |
| Open | MUI's menu: a paper below the trigger, at least as wide as its items, with 8px of padding above and below the list |
| Item | MUI's: the label in `body1` and `text.primary`, the icon in `action.active`, `secondary` in `text.secondary` at the end |
| Hover | `action.hover` background |
| Keyboard focus | The theme's focus ring, from [0001](./0001-button.md#styling-hooks), on the focused item |
| Disabled item | MUI's: at `action.disabledOpacity`, skipped by the arrow keys |
| With `divider` | A 1px `divider` line below the item, with MUI's 8px margins |
| `current` | MUI's selected background, `primary.main` at `action.selectedOpacity`, and `aria-current="page"`. Focus still starts on the first enabled item |
| `dense` | MUI's dense items |
| Empty | `items={[]}`: the menu opens with no items, and focus goes to the menu itself |

## Styling hooks

- **Theme keys:** `components.CmMenu`, with the slots `root`, `paper` and `item`, and default props for every Menu prop. The parts also use `MuiMenu`, `MuiPopover`, `MuiPaper`, `MuiMenuItem`, `MuiListItemIcon` and `MuiListItemText`.
- **Slots:** `menu` for MUI's `Menu`, `item` for every `MenuItem`, `itemIcon` and `itemText`. The paper is reached with `sx` and `className`.
- **Default look:** MUI's menu, with colors, font, radius and shadow from the library's design tokens. No theme change is needed. Select and Autocomplete already use MUI's menu and popper surfaces with the same tokens, so Menu looks like their option lists.

## Accessibility

- **Semantics:** the trigger has `aria-haspopup="menu"`, and `aria-expanded` and `aria-controls` while open. The menu is a `<ul role="menu">` in a portal, with `aria-labelledby` pointing at the trigger. Each item is an `<li role="menuitem">`, or an `<a role="menuitem">` for a link.
- **Keyboard,** following the WAI-ARIA menu button pattern:
  - On the trigger, `Enter` and `Space` open the menu and focus the first enabled item. `ArrowDown` does the same. `ArrowUp` opens it and focuses the last enabled item.
  - In the menu, `ArrowDown` and `ArrowUp` move to the next and previous enabled item, wrapping at the ends. `Home` and `End` move to the first and last.
  - Typing a character moves to the next item whose text starts with it, as in MUI.
  - `Enter` and `Space` choose the focused item. On a link, `Enter` follows it.
  - `Escape` closes the menu and returns focus to the trigger.
  - `Tab` closes the menu and returns focus to the trigger, as MUI does.
- **Naming:** the menu is named by the trigger. Each item is named by its `label` and `secondary`. An icon-only trigger needs `aria-label`, as in the second example.
- **Focus:** opening moves focus into the menu. Closing, by any means, returns focus to the trigger, through MUI's `Modal`. A click outside closes the menu.
- **Contrast:** labels are `text.primary` on `background.paper`, at 18 or more on both schemes, and `secondary` is `text.secondary`, at 7.15 or more.

## Behavior and edge cases

- **Duplicate ids:** React logs key warnings. Ids must be unique.
- **A trigger that isn't focusable,** such as an Avatar on its own: the menu can't be opened with the keyboard. Wrap it in a button, such as MUI's `IconButton`.
- **A trigger with its own `onClick` that calls `preventDefault()`:** the menu doesn't open, so a consumer can cancel it.
- **Controlled `open` without a trigger click:** the menu anchors to the trigger through its `ref`, so it can open from code, such as from a keyboard shortcut.
- **An item's `onClick` that opens a dialog:** the menu closes first and returns focus to the trigger. The dialog then takes focus and returns it to the trigger when it closes.
- **Long labels:** they don't wrap, and the menu grows up to the window's width minus 16px, as in MUI. Keep labels short.
- **Many items:** the menu scrolls once it reaches the window's height. More than about ten items belongs in Autocomplete or a List.
- **Near the edge of the window:** MUI's popover moves the menu to stay inside the window.
- **Destructive items:** an item such as "Delete" keeps the normal text color. See [Open questions](#open-questions).
- **Without the library theme:** Menu renders with the surrounding MUI theme.
- **Server Components:** Menu is a client component. `onClick` and `onItemClick` are functions, so items with them can't come from a Server Component.

## Acceptance criteria

- [ ] Renders only the trigger while closed, with `aria-haspopup="menu"` and without `aria-expanded`.
- [ ] Clicking the trigger opens a `menu` named by the trigger, with one `menuitem` for each item, in order, showing `label`, `icon` and `secondary`. The trigger then has `aria-expanded="true"` and `aria-controls` pointing at the menu.
- [ ] Opens below the trigger with `placement="bottom-start"`, and at the end with `bottom-end`. `slotProps.menu.anchorOrigin` wins over `placement`.
- [ ] Choosing an item calls its `onClick`, then `onItemClick` with the event and the item's `id`, then closes the menu.
- [ ] An item with `href` renders a link with `role="menuitem"`, through the theme's `MuiButtonBase.defaultProps.LinkComponent`.
- [ ] A disabled item can't be chosen and is skipped by the arrow keys.
- [ ] An item with `current` has `aria-current="page"` and the selected class.
- [ ] Works controlled with `open` and `onOpenChange`, and uncontrolled with and without `defaultOpen`, without React or MUI warnings.
- [ ] The trigger's own `onClick`, `id` and `ref` keep working, and a `preventDefault()` in its `onClick` stops the menu from opening.
- [ ] `ArrowDown` on the trigger opens the menu on the first enabled item, and `ArrowUp` on the last.
- [ ] `Escape` and `Tab` close the menu and return focus to the trigger.
- [ ] `divider` and `dense` reach MUI's components.
- [ ] `ref`, `className` and `sx` reach the paper.
- [ ] `slotProps.menu`, `slotProps.item`, `slotProps.itemIcon` and `slotProps.itemText` reach their elements.
- [ ] The root, paper and items have the `CmMenu-root`, `CmMenu-paper` and `CmMenu-item` classes.
- [ ] Type check: `Id` is inferred from `items`, and `onItemClick` receives that type.
- [ ] A project-level `CmMenu.defaultProps.placement` of `'bottom-end'` applies to every Menu.
- [ ] A project-level `CmMenu` `styleOverrides.paper` object changes the paper.
- [ ] Type check: `createCmTheme({ components: { CmMenu: { defaultProps: { dense: true }, styleOverrides: { item: { minHeight: 40 } } } } })` compiles, and an unknown slot name fails.
- [ ] An instance-level `sx` value overrides the theme.
- [ ] Under another MUI theme, without `CmThemeProvider`, Menu renders with that theme.
- [ ] Works with the keyboard as listed under Accessibility.
- [ ] Storybook has a story with a Button trigger, one with an icon-button trigger, one with icons, shortcuts and dividers, one with links, one with a disabled item, one controlled, one dense, and one showing a theme override.
- [ ] `Menu`, `MenuProps` and `MenuItemData` are exported from `src/index.ts`, and `Menu` is added to the public API and `'use client'` lists in `tests/dist.test.ts`.

## Out of scope

- Submenus.
- Items with a checked state, as `menuitemcheckbox` or `menuitemradio`.
- Group headings inside the menu. Use `divider` between groups.
- A menu that opens on right-click, at the pointer.
- Keeping the menu open after a choice.
- A color for destructive items.
- Exporting MUI's `MenuItem` for consumers who assemble menus themselves. They can import it from MUI.

## Open questions

- **Destructive items:** no `error` color in the library theme meets 4.5:1 as text on dark `background.paper`. `error.main` is 2.04 and `error.light` 3.04, while `red[300]` would be 5.76. Decide whether to add a dark-mode text color for errors to the theme, which would also help TextField's error text, before adding `color="error"` to items.
- **Navigation menus:** Navbar ([0025](./0025-navbar.md)) uses Menu for groups of links. The WAI-ARIA authoring practices prefer a disclosure with a plain list of links for site navigation over `role="menu"`. Confirm that Navbar reuses Menu, or add a disclosure mode.
