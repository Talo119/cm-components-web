# 0018: Card

- **Status:** Implemented
- **Date:** 2026-11-10
- **Kind:** Simple
- **Depends on:** [0000](./0000-architecture.md), [0001](./0001-button.md), [0003](./0003-typography.md), [0011](./0011-avatar.md)

## Purpose

Groups the content and actions about one subject, such as a product, a person or a report, in a box that stands apart from the page. MUI's `Card` is only the box. A title needs `CardHeader`, an image `CardMedia`, padded content `CardContent`, and a row of buttons `CardActions`. This library's `Card` takes `title`, `subheader`, `avatar`, `headerAction`, `image` and `actions` props and puts those parts together in a fixed order, so a consumer doesn't assemble them, as the architecture spec's goals ask.

**Use it for:** an item in a grid or list of similar items, such as products or projects. A summary on a dashboard, such as "Revenue this month". A self-contained section of a settings page, with its own actions.

**Don't use it for:**

- Text that should read as part of the page. Use Typography in the page's own layout.
- A message about a task or the page. Use Alert.
- A row in a list of many items. Use List or Table, which are on the [roadmap](./roadmap.md).
- A whole card that opens something when clicked. That's out of scope for this version. Put a Link in the title or a Button in `actions` instead.

## Usage

```tsx
import { Avatar, Button, Card, Link, Typography } from '@cmotino/cm-web-components'
import IconButton from '@mui/material/IconButton'
import MoreVertIcon from '@mui/icons-material/MoreVert'

<Card title="Revenue" subheader="This month">
  <Typography variant="h3">$24,300</Typography>
</Card>

<Card
  component="article"
  image={{ src: product.photoUrl, alt: '', height: 180 }}
  title={<Link href={`/products/${product.id}`}>{product.name}</Link>}
  subheader={product.price}
  actions={<Button size="small" onClick={() => addToCart(product.id)}>Add to cart</Button>}
  slotProps={{ title: { component: 'h3' } }}
  sx={{ maxWidth: 320 }}
>
  <Typography variant="body2" color="text.secondary">{product.summary}</Typography>
</Card>

<Card
  variant="outlined"
  avatar={<Avatar src={user.photoUrl} alt="" />}
  title={user.name}
  subheader={user.role}
  headerAction={
    <IconButton aria-label={`Options for ${user.name}`} onClick={openMenu}>
      <MoreVertIcon />
    </IconButton>
  }
/>
```

## API

`Card` is a component of this library, in `src/components/Card/`, built on MUI's `Card`, `CardHeader`, `CardMedia`, `CardContent` and `CardActions`.

```ts
export { Card } from './Card.tsx'
export type { CardProps, CardImage } from './Card.types.ts'
```

It takes MUI's `Card` props, such as `variant`, `raised`, `elevation`, `square`, `component`, `sx` and `className`, which reach the root. It adds or changes:

| Prop | Type | Default | Required | Description |
| --- | --- | --- | --- | --- |
| `title` | `ReactNode` | `undefined` | No | The card's title, in the header. Replaces the HTML `title` attribute |
| `subheader` | `ReactNode` | `undefined` | No | A line below the title, in `text.secondary` |
| `avatar` | `ReactNode` | `undefined` | No | Shown before the title, such as an Avatar |
| `headerAction` | `ReactNode` | `undefined` | No | Shown at the end of the header, such as an icon button that opens a menu |
| `image` | `CardImage` | `undefined` | No | An image at the top of the card, the full width of the card |
| `children` | `ReactNode` | `undefined` | No | The body, inside MUI's `CardContent` with its padding |
| `actions` | `ReactNode` | `undefined` | No | A row at the bottom, inside MUI's `CardActions`, such as Buttons |
| `slotProps` | See below | `undefined` | No | Props for inner parts |

```ts
export interface CardProps extends Omit<MuiCardProps, 'title' | 'children'> {
  title?: ReactNode
  subheader?: ReactNode
  avatar?: ReactNode
  headerAction?: ReactNode
  image?: CardImage
  children?: ReactNode
  actions?: ReactNode
  slotProps?: {
    header?: Partial<Omit<CardHeaderProps, 'title' | 'subheader' | 'avatar' | 'action'>>
    title?: Partial<TypographyProps>
    subheader?: Partial<TypographyProps>
    media?: Partial<CardMediaProps<'img'>>
    content?: Partial<CardContentProps>
    actions?: Partial<CardActionsProps>
  }
}
```

**Order:** the image, then the header, then the content, then the actions. Each part is only rendered when its props are set: the header when any of `title`, `subheader`, `avatar` or `headerAction` is, the content when `children` is, and the actions when `actions` is. A Card with none of them is an empty box.

**`slotProps.title` and `slotProps.subheader`** reach MUI's `CardHeader` title and subheader `Typography`, through its own `slotProps`. Use `component` there to make the title a heading, as in the second example.

**Typing:** `Card` is typed as `(props: CardProps) => ...`. MUI's `Card` is an `OverridableComponent`, but its only use of `component` here is a different root element, such as `article` or `section`, which `CardProps` allows. Props of another component passed through `component` aren't type-checked.

### Exceptions to the architecture spec

| Rule | Exception | Reason |
| --- | --- | --- |
| Section 2: remaining props reach the root | `children` goes inside `CardContent`, not directly in the root, and `title` isn't the HTML attribute | Padded content is the usual case. A consumer who wants to lay out the root directly uses MUI's `Card` |

No `'use client'` directive is needed, because `Card.tsx` uses no hooks and passes no functions of its own. Card can be rendered from a Server Component, as listed under Behavior and edge cases.

## Data shapes

```ts
export interface CardImage {
  /** The image's URL. */
  src: string
  /** Text for screen readers. `''` when the image is decorative, such as a photo next to the product's name. */
  alt: string
  /** The image's height, in pixels or any CSS length. Without it, the image keeps its own height. */
  height?: number | string
}
```

The image is rendered as an `<img>` through MUI's `CardMedia` with `component="img"`, with `object-fit: cover`, so it fills the width and is cropped to `height`. `height` is set as an inline style, not the HTML `height` attribute, which only takes pixels. A `style` in `slotProps.media` is merged with it.

## Variants and states

| Variant or state | Behavior or appearance |
| --- | --- |
| Default (`elevation`) | `background.paper` with `shadows[1]`, the library's soft `baseShadow`, and the theme's 8px radius. In dark mode MUI adds its light overlay for elevation 1 |
| `variant="outlined"` | No shadow, and a 1px border in `divider` |
| `raised` | `shadows[8]`, MUI's stronger shadow |
| With a header | 16px padding. The title is `h5` without an avatar and `body2` with one. The subheader is `body1` without an avatar and `body2` with one, in `text.secondary` |
| With an image | The image at the top, the full width of the card, with the card's top corners rounded by its `overflow: hidden` |
| With content | 16px padding, and 24px below when it's the last part |
| With actions | A row with 8px padding, and 8px between items |
| Hover, focus, active | Don't apply to the card itself. Its links and buttons have their own states |
| Empty | An empty box. A consumer shows a message as `children` |

## Styling hooks

- **Theme keys:** the keys of the MUI parts Card is built from: `MuiCard`, `MuiCardHeader`, `MuiCardMedia`, `MuiCardContent`, `MuiCardActions`, and `MuiPaper` for the box. Card has no `CmCard` key, because it's a simple component and the MUI keys already reach every part.
- **Slots:** `header` for `CardHeader`, `title` and `subheader` for its two `Typography` elements, `media` for `CardMedia`, `content` for `CardContent` and `actions` for `CardActions`. The root is reached with `sx` and `className`.
- **Default look:** no theme change. The box comes from `MuiPaper` with the library's tokens: `background.paper`, the `baseShadow` that [section 3 of the architecture spec](./0000-architecture.md#3-styling-and-theming) puts in `shadows[1]`, and the 8px radius. The text uses the library's typography.

## Accessibility

- **Semantics:** the root is a `<div>` with no role. For an item in a list or feed, pass `component="article"`, as in the second example. For a section of a page, pass `component="section"` with `aria-labelledby` pointing at the title.
- **Headings:** MUI renders the title as a `<span>`, so it isn't in the page's heading outline. Pass `slotProps.title={{ component: 'h3' }}`, with the level that fits the page, so screen reader users can jump between cards. See [Open questions](#open-questions).
- **Images:** `alt` is required by `CardImage`. Pass `''` when the image repeats what the title says, so screen readers skip it.
- **Keyboard:** None for the card itself. `Tab` reaches the links and buttons inside it, in the order image, header, content and actions.
- **Naming:** the card has no accessible name unless the consumer gives it one, such as through `aria-labelledby` with `component="section"`. Buttons that repeat on every card, such as "Add to cart", should say which item they're for, through `aria-label` or visually hidden text, so they make sense out of context.
- **Contrast:** the title is `text.primary` on `background.paper`, at 18.00:1 in light mode and 19.09:1 in dark mode. The subheader is `text.secondary`, at 7.15 and 7.25. See [Open questions](#open-questions) for the card's edge.

## Behavior and edge cases

- **Long titles:** wrap. With `headerAction`, the action stays at the top end and the title wraps beside it.
- **Long content:** the card grows. A fixed height and scrolling are the consumer's, with `sx`.
- **Cards in a grid:** cards with different amounts of content have different heights. A grid with equal heights needs the consumer's layout, such as CSS grid with `height: 100%` on each card through `sx`.
- **Images that fail to load:** the browser shows its broken image icon and the `alt` text, in the image's `height`. A fallback image is the consumer's.
- **Images without `height`:** the card's height changes when the image loads. Pass `height` in a grid, so the layout doesn't move.
- **Narrow screens:** the card fills its container, up to any `maxWidth` the consumer sets. The actions stay in one row and can overflow, because MUI's `CardActions` doesn't wrap. Pass `slotProps.actions={{ sx: { flexWrap: 'wrap' } }}` for many actions. Its 8px spacing is a left margin, so wrapped rows aren't aligned and have no gap between them.
- **Without the library theme:** Card renders with the surrounding MUI theme and its shadow.
- **Server Components:** Card can be rendered from a Server Component. Content with event handlers, such as an `actions` Button with `onClick`, must come from a client component.

## Acceptance criteria

- [ ] With `title` and `subheader`, renders both inside the header, with the subheader in `text.secondary`.
- [ ] With `avatar` and `headerAction`, renders them before and after the title.
- [ ] With `image`, renders an `<img>` with `src`, `alt` and its `height` as a style, before the header.
- [ ] `children` render inside `CardContent`, and `actions` inside `CardActions`, after the content.
- [ ] Each part is only rendered when its props are set. A Card with only `children` has no header.
- [ ] `slotProps.title={{ component: 'h3' }}` renders the title as an `<h3>`.
- [ ] `component="article"` renders the root as an `<article>`.
- [ ] `variant="outlined"` renders a border and no shadow.
- [ ] `ref` reaches the root element.
- [ ] `className`, `sx` and other props, such as `data-*` and `aria-labelledby`, reach the root element.
- [ ] Each slot in `slotProps` reaches its element.
- [ ] Type check: `title` accepts a `ReactNode`, and `image` without `alt` fails.
- [ ] Under the library theme, the card has `background.paper`, `shadows[1]` and the 8px radius.
- [ ] A project-level `MuiCard` `styleOverrides.root` object changes the box.
- [ ] A project-level `MuiCardHeader` `styleOverrides.title` object changes the title.
- [ ] An instance-level `sx` value overrides the theme.
- [ ] Under another MUI theme, without `CmThemeProvider`, Card renders with that theme.
- [ ] Storybook has a story for every variant, one for each combination of parts, one with a heading title and a Link, one grid of cards with images, and one showing a theme override.
- [ ] `Card`, `CardProps` and `CardImage` are exported from `src/index.ts`, and `Card` is added to the public API list in `tests/dist.test.ts`.

## Out of scope

- A card that's clickable as a whole, through MUI's `CardActionArea`. It can't contain other buttons or links, such as `headerAction` and `actions`, so it needs its own design.
- Other image positions, such as beside the content or below the header, and media other than images, such as video.
- Exporting MUI's `CardHeader`, `CardMedia`, `CardContent`, `CardActions` and `CardActionArea`. Consumers who need another layout use MUI's parts directly.
- Equal heights in a grid.
- Selectable cards, expanding cards and loading placeholders.

## Open questions

- **Default heading:** MUI's title is a `<span>`, which keeps cards out of the heading outline unless each consumer remembers `slotProps.title`. The library can't know the right level, but a default such as `h3` might be closer to right than no heading. Decide whether to keep MUI's `<span>`.
- **Card edge:** `background.paper` is 1.05:1 against the light background and 1.06:1 against the dark one, so the card's edge comes only from its soft shadow, and in dark mode the shadow is dark on a dark page. The `outlined` border, `divider`, is 1.20 and 1.35. WCAG doesn't require the edge to show, but the design should confirm it, or make `outlined` the default.

## Verified behavior

Checked on 2026-11-10 against the source of MUI 9.5.0 in `node_modules`, with contrast computed with MUI's `getContrastRatio` on the palette of `createCmTheme()`, with translucent colors blended over the page. The rows from the source were rechecked on implementing, and the rendered rows are covered by `Card.test.tsx` in jsdom. Recheck when upgrading MUI.

| Check | Result |
| --- | --- |
| `slots` and `slotProps` in `Card.d.ts` | Not present. `Card` is an `OverridableComponent` |
| Root in `Card.js` | MUI's `Paper` with `overflow: hidden`. `raised` sets `elevation={8}`, and otherwise Paper's default of 1 applies |
| Elevation in `Paper.js` | Sets `--Paper-shadow` to `shadows[elevation]`, and in dark mode `--Paper-overlay` to `overlays[elevation]` as a background image. `outlined` gets a 1px `divider` border and no shadow |
| Slots in `CardHeader.d.ts` | `root`, `avatar`, `action`, `content`, `title` and `subheader` |
| Title in `CardHeader.js` | `Typography` with `variant` `h5`, or `body2` with an avatar, and `component="span"`. The subheader is `body1`, or `body2` with an avatar, with `color="textSecondary"` and `component="span"` |
| Padding | `CardHeader` 16px, `CardContent` 16px with 24px below the last child, `CardActions` 8px |
| `CardActions` in `CardActions.js` | `display: flex` with no wrapping. Without `disableSpacing`, every item after the first gets `margin-left: 8px` |
| `CardMedia` with `component="img"` in `CardMedia.js` | Renders an `<img>` with `src` from `image`, `object-fit: cover` and `width: 100%`. Other props, such as `alt` and `height`, are spread onto it |
| `background.paper` against `background.default` | 1.05 light, 1.06 dark |
| `divider` over the page against the page | 1.20 light, 1.35 dark |
| Text on `background.paper` | `text.primary` 18.00 light, 19.09 dark. `text.secondary` 7.15 light, 7.25 dark |
| Title and subheader slots in `CardHeader.js` | `variant` and `component="span"` are passed as defaults, so `slotProps.title.component` replaces the `<span>` |
| Rendered: order | The `<img>`, the header, the content and the actions, as the root's children in that order |
| Rendered: shadow | `--Paper-shadow` resolves to the light `baseShadow`, and to `shadows[8]` with `raised`. `outlined` has a 1px solid border and no `elevation` class |
| Rendered: headings | `slotProps.title={{ component: 'h3' }}` gives an `<h3>`, which can hold a Link |
| Rendered: `slotProps.header.slotProps` | Its `title` and `subheader` apply when `slotProps.title` and `slotProps.subheader` aren't set |
