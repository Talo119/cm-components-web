# 0019: Tabs

- **Status:** Implemented
- **Date:** 2026-11-10
- **Kind:** Composite
- **Depends on:** [0000](./0000-architecture.md), [0004](./0004-link.md)

## Purpose

Splits related content into panels that share one place on the page, with a row of tabs to switch between them, such as "Details", "Activity" and "Settings" on a project page. MUI's `Tabs` and `Tab` provide the tab row, the indicator, scrolling and the keyboard handling, but MUI has no tab panel in `@mui/material`, so each project wires the ids, `aria-controls`, `aria-labelledby` and hidden panels itself. This library's `Tabs` takes an `items` array with each tab's label and content, renders the panels and links them, and can also render tabs that are links, for navigation between pages through the project's router.

This is the library's first composite, so it also sets how a composite gets its `Cm<Name>` theme key, as [section 3 of the architecture spec](./0000-architecture.md#3-styling-and-theming) describes.

**Use it for:** a few views of the same subject, where the user switches back and forth, such as the sections of a record. Sub-pages of one section, where each tab is a URL, such as `/settings/profile` and `/settings/billing`.

**Don't use it for:**

- Steps that must happen in order. That's a stepper, which isn't on the [roadmap](./roadmap.md).
- Choosing a value or a filter, such as "Day", "Week" or "Month" above a chart. Use Button group, or Radio group in a form.
- The site's main navigation. Use Navbar or Sidebar, which are on the roadmap.
- Content the user needs to compare side by side. Show it on one page.
- Many sections, such as more than six. Users miss tabs that scroll out of view. Use a list or Sidebar.

## Usage

```tsx
import { Tabs, Typography } from '@cmotino/cm-web-components'
import type { TabItem } from '@cmotino/cm-web-components'

const items: TabItem[] = [
  { id: 'details', label: 'Details', content: <ProjectDetails /> },
  { id: 'activity', label: 'Activity', content: <ActivityFeed /> },
  { id: 'settings', label: 'Settings', content: <ProjectSettings />, disabled: !canEdit },
]

<Tabs aria-label="Project" items={items} />

<Tabs
  aria-label="Project"
  items={items}
  value={tab}
  onChange={(_, id) => setTab(id)}
  keepMounted
/>

// Tabs as links. The router is set once in the theme, as in 0004.
<nav aria-label="Settings">
  <Tabs
    items={[
      { id: '/settings/profile', label: 'Profile', href: '/settings/profile' },
      { id: '/settings/billing', label: 'Billing', href: '/settings/billing' },
    ]}
    value={pathname}
  />
</nav>
```

## API

`Tabs` is a component of this library, in `src/components/Tabs/`, built on MUI's `Tabs` and `Tab`, with panels of its own.

```ts
export { Tabs } from './Tabs.tsx'
export type { TabsProps, TabItem } from './Tabs.types.ts'
```

| Prop | Type | Default | Required | Description |
| --- | --- | --- | --- | --- |
| `items` | `readonly TabItem<Id>[]` | | Yes | The tabs, in display order |
| `value` | `Id \| null` | `undefined` | No | Controlled selected tab. `null` means none is selected |
| `defaultValue` | `Id \| null` | The first enabled item's `id` | No | Initial selected tab when uncontrolled |
| `onChange` | `(event: SyntheticEvent, value: Id) => void` | `undefined` | No | Called when the user selects a tab |
| `keepMounted` | `boolean` | `false` | No | If `true`, every panel stays in the DOM, hidden, so its state is kept when the user switches tabs |
| `variant` | `'standard' \| 'scrollable' \| 'fullWidth'` | `'standard'` | No | MUI's: tabs at their own width, a row that scrolls, or tabs that share the full width |
| `orientation` | `'horizontal' \| 'vertical'` | `'horizontal'` | No | With `vertical`, the tabs are a column at the start and the panel is beside them |
| `centered` | `boolean` | `false` | No | Centers the tabs. Only with `variant="standard"` and `horizontal` |
| `scrollButtons` | `'auto' \| true \| false` | `'auto'` | No | MUI's. Only with `variant="scrollable"` |
| `selectionFollowsFocus` | `boolean` | `false` | No | If `true`, moving focus with the arrow keys selects the tab. See Accessibility |
| `aria-label`, `aria-labelledby` | `string` | `undefined` | No | Name the tab list, not the root |
| `slotProps` | See below | `undefined` | No | Props for inner parts |

`Tabs` also takes `sx`, `className`, `ref` and other props of a `<div>`, which reach the root, as the architecture spec requires. It's generic, as `Tabs<Id extends string | number = string>`, and `Id` is inferred from `items`.

```ts
export interface TabsProps<Id extends string | number = string>
  extends Omit<ComponentProps<'div'>, 'onChange' | 'defaultValue'> {
  items: readonly TabItem<Id>[]
  value?: Id | null
  defaultValue?: Id | null
  onChange?: (event: SyntheticEvent, value: Id) => void
  keepMounted?: boolean
  variant?: MuiTabsProps['variant']
  orientation?: MuiTabsProps['orientation']
  centered?: boolean
  scrollButtons?: MuiTabsProps['scrollButtons']
  selectionFollowsFocus?: boolean
  sx?: SxProps<Theme>
  slotProps?: {
    /** MUI's `Tabs`, the tab row. Reaches its other props and its own slots. */
    tabs?: Partial<Omit<MuiTabsProps, 'value' | 'onChange' | 'children'>>
    /** Every MUI `Tab`. */
    tab?: Partial<Omit<MuiTabProps, 'value' | 'label' | 'icon' | 'disabled' | 'href'>>
    /** Every panel `<div>`. */
    panel?: ComponentProps<'div'>
  }
}
```

**How it maps to MUI:** each item becomes a MUI `Tab` with `value={item.id}`. `null` is passed to MUI as `false`, which is how MUI's `Tabs` shows no selection. `aria-label` and `aria-labelledby` are passed to MUI's `Tabs`, which puts them on the element with `role="tablist"`.

**Panels:** each item with `content` gets a `<div role="tabpanel">`, after the tab row. Without `keepMounted`, only the selected item's panel is rendered. With it, every panel is rendered and the others get `hidden`. Ids are built from one React `useId` and the item's index, as `${id}-tab-${index}` and `${id}-panel-${index}`, so item ids can be any string. A tab gets `aria-controls` while its panel is in the DOM, so the reference is always valid: without `keepMounted`, only the selected tab has it. The panel gets `aria-labelledby` pointing at its tab and `tabIndex={0}`. A hidden panel stays hidden even when a project sets its `display`.

**Link tabs:** an item with `href` renders its `Tab` as a link, through `MuiButtonBase.defaultProps.LinkComponent`, so a project's router works as set up in [0004](./0004-link.md#usage). This answers the [roadmap question](./roadmap.md#questions-for-later-specs) for Tabs: no router dependency, and the same theme setup as Link. A link tab has no panel. The selected link tab gets `aria-current="page"`. The consumer passes the current route as `value`, as in the last example, and `onChange` is optional.

**Uncontrolled selection:** if the selected item is removed from `items`, or becomes disabled, the selection falls back to the first enabled item, without calling `onChange`. A controlled Tabs keeps whatever `value` the consumer passes.

### Theme key

Tabs reads its props through `useThemeProps({ props, name: 'CmTabs' })`, and styles its parts with MUI's `styled`, with `name: 'CmTabs'` and the slots `root`, `tabs` and `panel`. The class names `CmTabs-root`, `CmTabs-tabs` and `CmTabs-panel` are added to those elements, so a project can target them. The key is declared through module augmentation in `Tabs.types.ts`, so it reaches consumers through the emitted declarations, as `baseShadow` does from `createCmTheme.ts`:

```ts
declare module '@mui/material/styles' {
  interface ComponentsPropsList {
    CmTabs: TabsProps<string | number>
  }
  interface ComponentNameToClassKey {
    CmTabs: 'root' | 'tabs' | 'panel'
  }
  interface Components<Theme = unknown> {
    CmTabs?: {
      defaultProps?: ComponentsProps['CmTabs']
      styleOverrides?: ComponentsOverrides<Theme>['CmTabs']
      variants?: ComponentsVariants<Theme>['CmTabs']
    }
  }
}
```

Later composites follow the same pattern, with their own name and slots.

### Exceptions to the architecture spec

| Rule | Exception | Reason |
| --- | --- | --- |
| Section 2: remaining props reach the root | `aria-label` and `aria-labelledby` reach the tab list | They name the tabs. On the root `<div>`, which has no role, they would name nothing |

`Tabs.tsx` starts with `'use client'`, because it calls `useId` and keeps state, and is added to `tests/dist.test.ts`.

## Data shapes

```ts
interface TabItemBase<Id extends string | number> {
  /** Unique within `items`. Used as the React key, as the value, and reported by `onChange`. */
  id: Id
  /** The tab's visible text. It's also the tab's accessible name. */
  label: ReactNode
  /** Shown with the label, before it by default. Placed with `slotProps.tab.iconPosition`. */
  icon?: ReactElement
  /**
   * Shown but not selectable, and skipped by the arrow keys.
   * @default false
   */
  disabled?: boolean
}

export type TabItem<Id extends string | number = string> = TabItemBase<Id> &
  (
    | { /** The panel shown when the tab is selected. */ content?: ReactNode; href?: never }
    | { /** Makes the tab a link. It then has no panel. */ href: string; content?: never }
  )
```

An item can have `content` or `href`, not both, so the type stops a link tab from also having a panel.

## Variants and states

| Variant or state | Behavior or appearance |
| --- | --- |
| Default | A row of tabs, 48px high, with the label in the theme's `button` typography, not uppercase. A 1px `divider` line under the row. The panel below, with 16px of padding above and below |
| Selected | The label in `primary.dark` in light mode and `primary.main` in dark mode, and a 2px `primary.main` indicator under the tab. See Styling hooks |
| Not selected | The label in `text.secondary` |
| Hover | MUI's ripple on press. The label doesn't change color on hover, as in MUI |
| Keyboard focus | The theme's focus ring around the tab, from [0001](./0001-button.md#styling-hooks) |
| Disabled tab | The label in `text.disabled`. It can't be selected or focused with the arrow keys |
| With `icon` | The icon above the label by default, as in MUI, making the tab 72px high. `slotProps.tab.iconPosition="start"` puts it before the label |
| `variant="scrollable"` | The row scrolls sideways, with arrow buttons at the ends when it overflows, except on touch screens |
| `variant="fullWidth"` | The tabs share the full width of the row |
| `orientation="vertical"` | The tabs are a column with the `divider` line on its end side, and the panel is beside them, with 16px of padding at the start and end |
| Link tabs | Look the same as other tabs |
| No selection | `value={null}`: no tab is selected or has an indicator, and no panel is shown |
| Empty | `items={[]}`: an empty tab row and no panel |

## Styling hooks

- **Theme keys:** `components.CmTabs`, with the slots `root`, `tabs` and `panel`, and default props for every Tabs prop. The tab row and tabs also use `MuiTabs`, `MuiTab` and `MuiTabScrollButton`.
- **Slots:** `tabs` for MUI's `Tabs`, `tab` for every MUI `Tab`, and `panel` for every panel. The root is reached with `sx` and `className`.
- **Default look:** MUI's tabs, with colors from the library's design tokens and the label not uppercased, which [0003](./0003-typography.md#styling-hooks) already does through `typography.button`. Tabs' own styles add the `divider` line on the panels' side of the tab row, the panel padding, and for `vertical`, a flex row around the tabs and panel, with spacing from `theme.spacing`. `src/theme/defaultTheme.ts` gains one rule for the selected label:

```ts
import { tabClasses } from '@mui/material/Tab'

components: {
  // ...earlier components, unchanged
  // `primary.main` is below 4.5:1 on the light backgrounds, so a selected
  // tab's label uses `primary.dark` in light mode, as Link does. In dark mode
  // `primary.dark` fails instead. Kept as an object, so a project's `root`
  // object merges with it.
  MuiTab: {
    styleOverrides: {
      root: {
        variants: [
          {
            props: { textColor: 'primary' },
            style: ({ theme }) => ({
              [`&.${tabClasses.selected}`]: {
                color: (theme.vars || theme).palette.primary.dark,
                ...theme.applyStyles('dark', { color: (theme.vars || theme).palette.primary.main }),
              },
            }),
          },
        ],
      },
    },
  },
},
```

**Why the selected label:** MUI draws it in `primary.main`, which is 4.04:1 on the light background and 3.84:1 on light paper, below the 4.5:1 that WCAG 2.2 AA asks for 14px text (1.4.3). `primary.dark` gives 6.64 and 6.31. In dark mode `primary.main` gives 4.87 and 4.60, and `primary.dark` only 2.96 and 2.80, so dark mode keeps MUI's color. The rule matches [0004](./0004-link.md#styling-hooks).

**This rule applies to every MUI `Tab`** with `textColor="primary"` under the library theme, which is the default inside MUI's `Tabs`. A project's own `root` object in `MuiTab.styleOverrides` merges with it. A function replaces it, because `deepmerge` doesn't merge functions. The documentation must state this.

## Accessibility

- **Semantics:** the tab row has `role="tablist"`, with `aria-orientation="vertical"` when vertical. Each tab is a `<button role="tab">` with `aria-selected`, or an `<a role="tab">` for link tabs. Each panel is a `<div role="tabpanel">`.
- **Keyboard:**
  - `Tab` moves focus to the selected tab, and from there to the panel. Only one tab is in the tab order.
  - `ArrowRight` and `ArrowLeft`, or `ArrowDown` and `ArrowUp` when vertical, move focus to the next or previous tab, wrapping at the ends and skipping disabled tabs. They're reversed in right-to-left layouts.
  - `Home` and `End` move focus to the first and last tab.
  - `Enter` and `Space` select the focused tab. On a link tab, `Enter` follows the link.
  - With `selectionFollowsFocus`, moving focus also selects. Use it when panels are quick to show, as the WAI-ARIA tabs pattern advises. Don't use it with link tabs, where each arrow key would navigate.
- **Naming:** each tab is named by its `label`. The tab list is named by `aria-label` or `aria-labelledby` on Tabs, which every example passes. Each panel is named by its tab, through `aria-labelledby`. An item whose `label` is only an icon has no name. That's out of scope.
- **Focus:** the panel has `tabIndex={0}`, so keyboard users reach it after the tabs even when it has nothing focusable. Selecting a tab doesn't move focus to the panel.
- **Link tabs:** they keep `role="tab"`, as MUI's navigation tabs do, so the arrow keys work and screen readers announce them as tabs. The selected one has `aria-current="page"`. Wrap them in a `<nav>` with a name, as in the last example. The WAI-ARIA tabs pattern is meant for panels, not navigation. See [Open questions](#open-questions).
- **Contrast:** the selected label as described under Styling hooks. Other labels are `text.secondary`, at 7.15 or more on both schemes. The indicator is `primary.main`, at 3.84 or more against the background, which meets 3:1 for a graphic that shows the selection. Disabled tabs are exempt.

## Behavior and edge cases

- **Duplicate ids:** React logs key warnings, and both tabs show as selected. Ids must be unique.
- **A `value` that isn't in `items`:** MUI logs an error, and no tab is selected. Use `null` for no selection.
- **Many tabs:** with `variant="standard"`, tabs that don't fit are cut off. Use `variant="scrollable"` when there are more than about four tabs or the screen is narrow. Scrolling keeps the selected tab in view.
- **Long labels:** a tab is between 90px and 360px wide, and a long label wraps inside it. Keep labels to a word or two.
- **Panel state:** without `keepMounted`, switching tabs unmounts the previous panel, so its form fields and scroll position are lost. Pass `keepMounted`, or keep the state outside Tabs.
- **Heavy panels:** with `keepMounted`, every panel renders up front, which is slow for many heavy panels. Without it, a panel renders only when its tab is selected.
- **Items without `content` or `href`:** the tab works and reports `onChange`, but shows no panel. That fits a consumer who renders the content outside Tabs.
- **Link tabs and `value`:** the router decides the selection, so a link tab looks selected only when the consumer's `value` matches it. A route below a tab, such as `/settings/billing/invoices`, needs the consumer to map it to the tab's id.
- **Vertical tabs on narrow screens:** the column takes width from the panel. A layout that switches to horizontal tabs on small screens is the consumer's, through `orientation`.
- **Without the library theme:** Tabs renders with the surrounding MUI theme and MUI's selected color.
- **Server Components:** Tabs is a client component. `items` can come from a Server Component, as long as each `label`, `icon` and `content` is serializable or a Server Component element.

## Acceptance criteria

- [ ] Renders a `tablist` named by `aria-label`, with one `tab` for each item, in order, named by its `label`.
- [ ] Uncontrolled, the first enabled item is selected, and its `content` is shown in a `tabpanel`.
- [ ] Clicking a tab selects it, shows its panel, and calls `onChange` with the event and the item's `id`.
- [ ] Works controlled with `value` and `onChange`, and uncontrolled with and without `defaultValue`, without React or MUI warnings.
- [ ] `value={null}` selects no tab and shows no panel.
- [ ] Each tab whose panel is in the DOM has `aria-controls` pointing at it, and the panel has `aria-labelledby` pointing at its tab and `tabIndex={0}`. Ids are valid when item ids contain spaces.
- [ ] Without `keepMounted`, only the selected panel is in the DOM. With it, every panel is, and the others are `hidden`, keeping their state.
- [ ] A disabled tab can't be selected and is skipped by the arrow keys.
- [ ] Uncontrolled, removing the selected item selects the first enabled item.
- [ ] An item with `href` renders a link, uses the theme's `MuiButtonBase.defaultProps.LinkComponent`, has no panel, and has `aria-current="page"` when selected.
- [ ] `orientation="vertical"` sets `aria-orientation="vertical"`, and `ArrowDown` and `ArrowUp` move focus.
- [ ] `variant`, `centered`, `scrollButtons` and `selectionFollowsFocus` reach MUI's `Tabs`.
- [ ] `ref` reaches the root `<div>`, and `className`, `sx` and other props, such as `data-*`, reach it too.
- [ ] `slotProps.tabs`, `slotProps.tab` and `slotProps.panel` reach their elements.
- [ ] The root, tab row and panels have the `CmTabs-root`, `CmTabs-tabs` and `CmTabs-panel` classes.
- [ ] Type check: `Id` is inferred from `items`, `onChange` receives that type, a `value` of another type fails, and an item with both `content` and `href` fails.
- [ ] Under the library theme, a selected tab's label is `primary.dark` in light mode and `primary.main` in dark mode.
- [ ] Under the library theme, keyboard focus on a tab shows the focus ring.
- [ ] A project-level `CmTabs.defaultProps.variant` of `'scrollable'` applies to every Tabs.
- [ ] A project-level `CmTabs` `styleOverrides.panel` object changes the panels.
- [ ] A project-level `MuiTab` `styleOverrides.root` object changes the tabs and keeps the library's selected color.
- [ ] Type check: `createCmTheme({ components: { CmTabs: { defaultProps: { keepMounted: true }, styleOverrides: { panel: { padding: 0 } } } } })` compiles, and an unknown slot name fails.
- [ ] An instance-level `sx` value overrides the theme.
- [ ] Under another MUI theme, without `CmThemeProvider`, Tabs renders with that theme.
- [ ] Works with the keyboard as listed under Accessibility.
- [ ] Storybook has a story for every variant and orientation, one with icons, one with a disabled tab, one with `keepMounted` and a form in a panel, one with link tabs, one with many scrollable tabs, and one showing a theme override.
- [ ] `Tabs`, `TabsProps` and `TabItem` are exported from `src/index.ts`, and `Tabs` is added to the public API and `'use client'` lists in `tests/dist.test.ts`.

## Out of scope

- Tabs with only an icon and no visible label.
- Closing, adding or reordering tabs.
- Loading a panel's content when it's first shown. A consumer renders a Progress inside `content` while it loads.
- Moving focus to the panel when a tab is selected.
- A badge or count on a tab, such as "Inbox (4)". The `label` can contain one, as text.
- Exporting MUI's `Tab` and a separate `TabPanel` for consumers who assemble tabs themselves.
- Mapping nested routes to link tabs.

## Open questions

- **Link tabs and the tabs role:** MUI's navigation tabs keep `role="tab"` on links, but the WAI-ARIA tabs pattern is for panels, and some screen readers announce "tab 1 of 2" for what is a page link. Confirm that link tabs keep MUI's approach, or decide that link tabs render plain links in a list with `aria-current`, losing the arrow keys.
- **Default variant:** `standard` cuts off tabs that don't fit, which fails on narrow screens. Decide whether the library defaults to `variant="scrollable"`, set through `CmTabs.defaultProps`.
