# @cmotino/cm-web-components

## 0.6.0

### Minor Changes

- c9e4bed: Add `Alert` and `AlertTitle`, re-exports of MUI's. The default theme now draws the severity icon of every standard and outlined MUI `Alert` in the alert's text color, instead of the severity's `main` color, which is below 3:1 for most severities on both color schemes. Filled alerts keep MUI's colors. This also applies to MUI's own `Alert` under the library theme. A project's `MuiAlert.styleOverrides.root` object merges with this rule, and a `root` function replaces it. Pass `role="status"` for messages that aren't urgent, because the default `role="alert"` interrupts screen readers.
- c9e4bed: Add `Autocomplete`, MUI's `Autocomplete` with the TextField built in. It takes `label`, `helperText`, `error`, `required` and `disabled`, `placeholder` and `variant`, and an `options` array of `{ value, label, disabled? }` with string or number values and string labels. `value`, `defaultValue` and `onChange` use the values, with their type, and `multiple` makes them arrays, shown as chips. `null` or `[]` means nothing is selected. With `name`, a hidden input per selected value submits the values, not the labels, with a form. `aria-label`, `aria-labelledby` and `aria-describedby` reach the combobox, and `aria-describedby` is joined with the helper text. With `required` and `multiple`, native validation passes once a value is selected. `slotProps.textField` reaches the TextField, and MUI's slots, such as `chip` and `listbox`, work as in MUI. `freeSolo`, `groupBy`, `renderInput` and MUI's option getters aren't supported.
- c9e4bed: Add `Card`, which builds MUI's `Card` from `title`, `subheader`, `avatar`, `headerAction`, `image` (`{ src, alt, height? }`), `children` and `actions`, in that order: the image, the header, the content, then the actions. Each part is only rendered when its props are set. MUI's `Card` props, such as `variant`, `raised` and `component`, reach the root. `slotProps` reaches the header, the title and subheader `Typography`, the image, the content and the actions. The title is a `<span>` unless `slotProps.title` sets a heading, such as `{ component: 'h3' }`.
- c9e4bed: Add `LinearProgress` and `CircularProgress`, re-exports of MUI's. Neither has an accessible name by default, so pass `aria-label` or `aria-labelledby`. The default theme now draws every MUI `LinearProgress` track in `divider`, instead of MUI's tint of the bar's color, which is below 3:1 against a `primary` bar on both color schemes. The `buffer` variant keeps MUI's colors. This also applies to MUI's own `LinearProgress` under the library theme. A project's own `MuiLinearProgress` `root` style override replaces this rule.
- c9e4bed: Add `Tabs`, which takes an `items` array of `{ id, label, icon?, disabled?, content? }`, or `href` in place of `content` for link tabs. Each item's `content` is shown in a `tabpanel` linked to its tab. Only the selected panel is rendered, unless `keepMounted` keeps every panel in the DOM, hidden. `value`, `defaultValue` and `onChange` use the item's `id`, with its type, and `null` means no tab is selected. Link tabs render through `MuiButtonBase.defaultProps.LinkComponent`, so they use the project's router, and the selected one has `aria-current="page"`. `aria-label` and `aria-labelledby` name the tab list. Tabs is the first composite, with its own `components.CmTabs` theme key for default props, variants and the `root`, `tabs` and `panel` slots. The default theme now colors a selected MUI `Tab`'s label `primary.dark` in light mode and `primary.main` in dark mode, so it meets 4.5:1 on both color schemes. This also applies to MUI's own `Tab` under the library theme. A project's `MuiTab.styleOverrides.root` object merges with this rule, and a `root` function replaces it.
- c9e4bed: Add `Tooltip`, a re-export of MUI's `Tooltip`, with no changes. Without `describeChild`, a string `title` becomes the child's `aria-label`, which suits icon-only buttons. Pass `describeChild` on a child with visible text, so it keeps its own name. Wrap a disabled button in a `<span>` so its tooltip opens on hover.

## 0.5.0

### Minor Changes

- 331774e: Add `Avatar`, a re-export of MUI's `Avatar` for the photo, initials or icon of a person or thing. When the image fails to load, it shows the children, then the first letter of `alt`, then a person icon. The default theme now draws every MUI `Avatar`'s initials, icons and fallback in `common.white` on `grey[500]`, instead of MUI's colors, which are below 4.5:1 on both color schemes. Avatars with a working image aren't affected. This also applies to MUI's own `Avatar` under the library theme. A project's own `MuiAvatar` `colorDefault` style override replaces these colors.
- 331774e: Add `Badge`, a re-export of MUI's `Badge` for a count or dot on the corner of another element. The badge is `aria-hidden`, so its information belongs in the child's accessible name. The default theme now sets `color="error"` on every MUI `Badge`, instead of MUI's `default`, which draws the number with no background. `error` is the only theme color whose text meets 4.5:1 on both color schemes. This also applies to MUI's own `Badge` under the library theme. A project changes it with `MuiBadge.defaultProps.color`.
- 331774e: Add `Chip`, a re-export of MUI's `Chip` for a tag, a status, a filter or a selected value. The default theme now changes every MUI `Chip`, including MUI's own and the tags in MUI's `Autocomplete`. On default-colored chips, the delete icon is `text.secondary` and `text.primary` on hover, instead of MUI's translucent icon, which is below 3:1. Initials in an avatar are `common.white`, instead of `grey[700]`, which is below 4.5:1 on the avatar. Colored chips keep MUI's colors. `MuiChip.defaultProps.skipFocusWhenDisabled` is now `true`. MUI otherwise leaves a disabled chip with only `onDelete` in the tab order, where `Backspace` still deletes it. A project's own `MuiChip` `deleteIcon` or `avatar` style override replaces the library's rule.
- 331774e: Add `Rating`, MUI's star rating with `label`, `helperText`, `error`, `required` and `disabled` built in. The root is a MUI `FormControl`. The stars sit in an element with `role="radiogroup"` named by the label, with `aria-describedby`, `aria-invalid` and `aria-required` from the helper text, `error` and `required`. A `readOnly` rating is an `img` named by the label and the value. `aria-label`, `aria-labelledby` and `aria-describedby` reach that element. `required` doesn't stop a native form submit, because MUI checks a hidden "Empty" radio when there's no value. The default theme now colors every MUI `Rating`'s filled stars `warning.main`, instead of MUI's hard-coded `#faaf00`, and its empty stars `grey[500]`, instead of `action.disabled`, which can't be seen against the background. This also applies to MUI's own `Rating` under the library theme. A project's own `MuiRating` `root` or `iconEmpty` style override replaces these colors.
- 331774e: Add `Slider`, MUI's `Slider` with `label`, `helperText`, `error` and `disabled` built in, for one value or a range. The root is a MUI `FormControl` that fills its container. `aria-label`, `aria-labelledby` and `aria-describedby` reach every thumb's `<input>`, and with `getAriaLabel` the root becomes a group named by the label. `onChange` gets a number for a number value and an array for an array. The default theme now gives every MUI `Slider` an opaque `grey[500]` rail, which meets WCAG 2.2 AA's 3:1 for the parts of a control on both color schemes. Disabled and inverted rails keep MUI's styles. This also applies to MUI's own `Slider` under the library theme. A project's own `MuiSlider` `rail` style override replaces this rule.

## 0.4.0

### Minor Changes

- 8f3f7ce: Add `TextField` and `Checkbox`. `TextField` is MUI's `TextField`. `Checkbox` adds `label`, `helperText`, `error`, `required` and `disabled` to MUI's `Checkbox`, with its root a MUI `FormControl`: `ref`, `sx` and other props reach that root, while `inputRef`, `aria-label`, `aria-labelledby` and `aria-describedby` reach the `<input>`. The default theme now gives outlined inputs a `grey[500]` border, which meets WCAG 2.2 AA's 3:1 for the edge of a control on both color schemes. This also applies to MUI's own outlined inputs, such as `Select` and `Autocomplete`, under the library theme. A project's own `MuiOutlinedInput` `notchedOutline` or `root` style override replaces this rule.
- 8f3f7ce: Add `Link`, MUI's `Link` with the library's type scale. The default theme now colors `color="primary"` links with `primary.dark` in light mode and `primary.main` in dark mode, so links in body text pass WCAG 2.2 AA contrast on both color schemes. This also applies to MUI's own `Link` used under the library theme. A project's `MuiLink.styleOverrides.root` object merges with this rule, but its own `root.variants` array or a `root` function replaces it. To use a router everywhere, set `MuiLink.defaultProps.component` and `MuiButtonBase.defaultProps.LinkComponent` in `createCmTheme`, as shown in the README.
- 8f3f7ce: Add `RadioGroup`, which takes an `options` array of `{ value, label, disabled? }` with string values, and `label`, `helperText`, `error`, `required` and `disabled`. It puts MUI's `FormControl`, `FormLabel`, `RadioGroup`, `FormControlLabel`, `Radio` and `FormHelperText` together and links them for screen readers. The value type is inferred from `options`, `onChange` receives `(event, value)`, and `null` means nothing is selected. `error` and `required` set `aria-invalid` and `aria-required` on the group, and `required` also sets `required` on every radio input. `row`, `color`, `size`, `name` and `slotProps` for each inner part are supported.
- 8f3f7ce: Add `Select`, built on MUI's `TextField` with `select`. It takes an `options` array of `{ value, label, disabled? }`, where `value` is a string or a number, and `onChange` receives `(event, value)` with the option's value and its type. `null` means nothing is selected, in `value` and `defaultValue`, without MUI's or React's warnings. TextField's props work as on TextField, except those for typing text, and `slotProps.option` reaches every `MenuItem`. `aria-label` names the combobox when there's no `label`. `multiple` and `native` aren't supported.
- 8f3f7ce: Add `Switch`, MUI's `Switch` with `label`, `helperText`, `error`, `required` and `disabled` built in, in the same way as `Checkbox`. The default theme now gives every MUI `Switch` an opaque `grey[500]` track when off, which meets WCAG 2.2 AA's 3:1 for the parts of a control on both color schemes. This also applies to MUI's own `Switch` under the library theme. A project's own `MuiSwitch` `track` style override replaces this rule.

## 0.3.0

### Minor Changes

- 7b0b152: Add `ButtonGroup`, MUI's `ButtonGroup` with the library's default look. The default theme now sets `disableElevation: true` on `MuiButtonGroup`, because a group's own value replaces `MuiButton`'s default for its buttons. Inside a group, the group's `color`, `size`, `variant` and other shared props likewise replace `MuiButton.defaultProps`, so set those on `MuiButtonGroup` too.
- 7b0b152: Add `Typography`, MUI's `Typography` with the library's type scale. The default theme now maps `subtitle1` and `subtitle2` to `<p>` instead of `<h6>`, so subtitles no longer appear as headings, and sets `typography.button.textTransform` to `none`, so the `button` variant and components that use it, such as `Tab` and `ToggleButton`, are no longer uppercase. Use `color="textSecondary"`, not `color="text.secondary"`, which has no effect in MUI 9.
  
  A `MuiButton.styleOverrides.root` function, which replaces the library's root styles, no longer brings back an uppercase label, because the label now follows `typography.button`.

## 0.2.0

### Minor Changes

- 8f54e73: Add `Button`, MUI's `Button` with the library's default look. The default theme now removes the uppercase label and elevation from MUI's `Button`, and turns on MUI's keyboard focus ring for every MUI component. Set `focusVisible: false` in `createCmTheme` to turn the ring off.
- 8f54e73: The default theme now has its own look: a blue `brand` primary color, gray text and backgrounds, and matching `info`, `success`, `warning` and `error` colors, each with light and dark values. Text uses `Inter, sans-serif` with new heading sizes, corners have an 8px radius, and `shadows[1]` is a soft shadow that changes with the color scheme through the new `palette.baseShadow` token. The library doesn't load Inter, so projects that want it should load it themselves, for example with `@fontsource/inter`.
